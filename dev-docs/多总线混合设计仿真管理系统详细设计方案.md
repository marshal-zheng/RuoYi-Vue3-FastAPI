## 一、系统概述

### 1.1 项目范围

本系统是一套面向多总线混合设计的仿真管理平台,支持以太网(LAN)、RS422/RS485串口、CAN总线、1553B总线等多种通信协议的混合设计与仿真验证。系统采用B/S架构,提供工程化的版本管理、拓扑设计、设备管理、协议配置和仿真分析功能。

**核心业务模块包括**:
- 工程管理: 项目全生命周期管理,支持多版本并行开发与固化
- 设备中心: 设备分类、设备模型、接口配置的统一管理
- 协议管理: 多总线协议的定义、配置和模板化管理
- 系统管理: 用户权限、角色管理、菜单配置、操作日志审计

### 1.2 系统概述

多总线混合设计仿真管理系统是一个面向总线系统设计与验证的综合性平台,旨在解决传统总线设计过程中存在的以下问题:

1. **多总线协同难题**: 支持LAN、RS422/RS485、CAN、1553B等多种总线协议在同一工程中的混合使用
2. **设计复杂度管理**: 通过图形化拓扑设计、设备模型库、协议模板等方式简化设计流程
3. **版本控制需求**: 提供完善的版本管理机制,支持设计方案的迭代、固化与回溯
4. **仿真验证能力**: 集成仿真引擎,实现总线负载分析、报文监控、带宽评估等功能
5. **团队协作支持**: 基于权限体系的多用户协同设计与审计跟踪

系统采用前后端分离架构,后端使用FastAPI提供高性能RESTful API,前端使用Vue 3构建响应式用户界面,通过AntV X6实现拓扑图形化编辑,整体技术栈先进、扩展性强。

### 1.3 研制目标

**功能目标**:
- 支持至少5种主流总线协议(LAN、RS422、RS485、CAN、1553B)的混合设计
- 提供可视化拓扑设计器,支持拖拽式设备布局与连线配置
- 实现工程全生命周期管理,包括版本控制、固化、克隆等功能
- 集成仿真引擎,支持报文级监控、带宽分析、冲突检测
- 建立设备模型库和协议模板库,提高设计复用率

**性能目标**:
- 系统响应时间: ≤2秒(常规操作)
- 并发用户数: ≥50用户
- 仿真实时性: 支持10ms级报文周期的实时仿真
- 拓扑规模: 单工程支持≥100个设备节点、≥200条总线连接
- 数据可靠性: 99.9%数据完整性保证

**质量目标**:
- 代码质量: 遵循PEP 8(Python)和Vue 3最佳实践
- 测试覆盖率: 核心业务逻辑≥80%
- 文档完善度: 接口文档、用户手册、部署指南齐全
- 可维护性: 模块化设计,低耦合高内聚
- 安全性: 通过JWT认证、RBAC权限控制、操作审计保障系统安全

## 二、系统功能要求

### 2.1 工程管理模块

#### 2.1.1 工程基本管理
- **工程创建**: 支持工程名称、编码、描述等基本信息配置
- **工程查询**: 提供工程列表查询、模糊搜索、高级筛选
- **工程编辑**: 支持工程基本信息修改
- **工程删除**: 支持逻辑删除(软删除),可恢复

#### 2.1.2 版本管理
- **版本创建**: 在工程下创建新版本,支持版本号、版本名称、描述配置
- **版本查询**: 展示工程的所有版本列表,支持按版本号、创建时间排序
- **版本编辑**: 修改未固化版本的基本信息
- **版本删除**: 删除未固化版本(固化版本不可删除)
- **版本克隆**: 基于现有版本创建新版本,复制拓扑、设备、协议配置
- **版本固化**: 将版本标记为固化状态,固化后不可修改,保证设计方案的不可变性
- **版本对比**: 对比不同版本间的拓扑差异、配置变化

#### 2.1.3 拓扑设计
- **图形化编辑**: 基于AntV X6的拓扑图设计器,支持拖拽式节点创建、连线
- **设备节点**: 从设备库中选择设备添加到拓扑图
- **总线连线**: 配置设备间的总线连接,支持不同协议类型
- **布局管理**: 支持自动布局(树形、层次、力导向)和手动调整
- **拓扑验证**: 检测环路、多连、负载冲突等设计问题
- **拓扑导出**: 导出拓扑图为图片或JSON配置文件

#### 2.1.4 仿真功能
- **仿真会话**: 基于特定版本创建仿真会话,支持启动、暂停、停止
- **报文监控**: 实时捕获并展示总线上的通信报文
- **带宽分析**: 统计各端口的带宽占用率,绘制带宽曲线
- **告警检测**: 识别环路、多连、带宽溢出等异常情况
- **数据注入**: 支持手动注入测试报文,验证系统响应
- **仿真记录**: 保存仿真会话的报文、带宽、告警数据,供后续分析

### 2.2 设备中心模块

#### 2.2.1 设备分类管理
- **分类创建**: 创建设备分类,如处理器、传感器、执行器等
- **分类查询**: 查看所有设备分类,支持分页
- **分类编辑**: 修改分类名称、描述
- **分类删除**: 删除空分类(含设备的分类需先迁移设备)
- **分类导出**: 导出分类列表为Excel

#### 2.2.2 设备管理
- **设备创建**: 创建设备,配置设备名称、分类、厂商、型号、版本等
- **设备查询**: 查询设备列表,支持按分类、总线类型筛选
- **设备编辑**: 修改设备基本信息
- **设备删除**: 删除设备(需检查是否被工程使用)
- **设备导出**: 导出设备列表为Excel
- **批量操作**: 支持批量导入设备

#### 2.2.3 设备接口配置
- **接口创建**: 为设备添加接口,配置接口名称、类型(LAN/RS422/RS485/CAN/1553B)
- **接口参数**: 配置接口的协议参数,如IP地址、端口号、波特率、CAN ID等
- **报文配置**: 为接口配置收发报文列表,关联协议模板
- **接口位置**: 指定接口在设备图标上的位置(上/下/左/右)
- **接口编辑**: 修改接口配置
- **接口删除**: 删除接口(需检查拓扑连线依赖)

### 2.3 协议管理模块

#### 2.3.1 协议模板管理
- **协议创建**: 创建协议,配置协议名称、类型(LAN/RS422/RS485/CAN/1553B)
- **协议查询**: 查询协议列表,支持按类型筛选
- **协议编辑**: 修改协议基本信息和配置
- **协议删除**: 删除未被引用的协议
- **协议导出**: 导出协议配置为JSON或Excel
- **协议固化**: 将成熟的协议标记为固化,防止误修改

#### 2.3.2 协议配置
- **以太网协议**: 配置传输方式(UDP单播/组播/广播、TCP)、IP地址、端口、速率(10M/100M/1000M)
- **RS422协议**: 配置波特率(9.6K~921.6K)、数据位、停止位、校验位、传输方式
- **RS485协议**: 配置波特率、数据位、停止位、校验位、从机地址
- **CAN协议**: 配置波特率(125K/250K/500K/1000K)、帧类型(标准帧/扩展帧)、CAN ID
- **1553B协议**: 配置速率(1M)、传输方式(BC->RT/RT->BC/RT->RT)、RT地址、子地址

#### 2.3.3 报文字段定义
- **字段列表**: 定义协议的字段列表,包括字段名称、数据类型、偏移量、长度
- **数据类型**: 支持UINT8/16/32、INT8/16/32、FLOAT、DOUBLE、STRING、BOOL
- **字节序**: 配置大端/小端字节序
- **默认值**: 设置字段默认值
- **有效范围**: 定义字段的有效值范围
- **校验字段**: 配置CRC、校验和等校验字段

#### 2.3.4 错误处理策略
- **不判断**: 不进行错误检测
- **超时重传**: 配置超时时间和重传次数
- **CRC校验**: 配置CRC算法(CRC16/CRC32)
- **奇偶校验**: 配置奇校验或偶校验

### 2.4 系统管理模块

#### 2.4.1 用户管理
- **用户创建**: 创建用户,配置用户名、昵称、邮箱、手机号、部门、岗位、角色
- **用户查询**: 查询用户列表,支持按部门、状态筛选
- **用户编辑**: 修改用户信息
- **用户删除**: 逻辑删除用户
- **密码重置**: 管理员重置用户密码
- **用户导入**: 批量导入用户
- **用户导出**: 导出用户列表

#### 2.4.2 角色管理
- **角色创建**: 创建角色,配置角色名称、权限字符串、显示顺序
- **角色查询**: 查询角色列表
- **角色编辑**: 修改角色信息
- **角色删除**: 删除角色(需检查关联用户)
- **菜单权限**: 为角色分配菜单权限
- **数据权限**: 配置角色的数据范围(全部/自定义/本部门/本部门及以下)

#### 2.4.3 菜单管理
- **菜单创建**: 创建菜单,配置菜单名称、路径、组件、图标、类型(目录/菜单/按钮)
- **菜单查询**: 查询菜单树
- **菜单编辑**: 修改菜单配置
- **菜单删除**: 删除菜单(需检查子菜单)
- **权限标识**: 配置菜单的权限标识(perms),用于后端权限验证
- **菜单排序**: 调整菜单显示顺序

#### 2.4.4 日志管理
- **操作日志**: 记录用户的所有操作(新增/修改/删除/导出/导入等)
- **登录日志**: 记录用户登录/登出行为、IP地址、浏览器、操作系统
- **日志查询**: 支持按操作类型、操作人、时间范围查询
- **日志导出**: 导出日志为Excel
- **日志清理**: 定期清理过期日志

## 三、系统框架设计

### 3.1 设计原则

#### 3.1.1 高内聚低耦合
- **模块化设计**: 系统按业务模块划分,每个模块独立封装,职责单一
- **分层架构**: Controller、Service、DAO、Entity分层,层间依赖单向
- **依赖注入**: 通过FastAPI依赖注入解耦组件依赖关系

#### 3.1.2 可扩展性
- **插件化协议**: 协议处理器采用策略模式,新增协议类型仅需实现接口
- **可配置化**: 系统参数、字典数据通过数据库配置,无需修改代码
- **微服务预留**: 采用RESTful API设计,便于未来拆分为微服务架构

#### 3.1.3 高性能
- **异步I/O**: 数据库操作全部使用async/await异步编程
- **连接池**: 数据库连接池、Redis连接池复用连接
- **缓存策略**: 字典数据、用户权限等热点数据缓存到Redis
- **分页查询**: 大数据量列表查询采用分页,避免全表扫描

#### 3.1.4 安全性
- **认证授权**: JWT Token认证 + RBAC权限控制
- **密码安全**: Bcrypt加密存储密码
- **SQL注入防护**: 使用ORM(SQLAlchemy)参数化查询
- **XSS防护**: 前端输入校验,后端输出转义
- **操作审计**: 记录所有敏感操作日志

#### 3.1.5 可维护性
- **代码规范**: 遵循PEP 8(Python)、Vue 3风格指南
- **文档化**: API文档(FastAPI自动生成)、代码注释、用户手册
- **版本控制**: Git版本管理,语义化版本号
- **单元测试**: 核心业务逻辑编写单元测试

### 3.2 软件架构设计

#### 3.2.1 总体架构

系统采用**前后端分离的B/S架构**,分为四层:

```
┌─────────────────────────────────────────────────────────────┐
│                       展示层 (Presentation)                  │
│  Vue 3 + Element Plus + TypeScript + AntV X6               │
│  - 用户界面  - 图形化拓扑编辑  - 数据可视化                 │
└─────────────────────────────────────────────────────────────┘
                              │ HTTP/WebSocket
┌─────────────────────────────────────────────────────────────┐
│                       应用层 (Application)                   │
│  FastAPI + Python 3.9+                                      │
│  - RESTful API  - WebSocket  - JWT认证  - RBAC权限         │
└─────────────────────────────────────────────────────────────┘
                              │
┌─────────────────────────────────────────────────────────────┐
│                       业务层 (Business)                      │
│  Service + DAO                                              │
│  - 业务逻辑  - 数据访问  - 事务管理  - 缓存策略             │
└─────────────────────────────────────────────────────────────┘
                              │
┌─────────────────────────────────────────────────────────────┐
│                       数据层 (Data)                          │
│  MySQL 8.0 + Redis 5.0                                      │
│  - 持久化存储  - 缓存  - 会话管理                           │
└─────────────────────────────────────────────────────────────┘
```

#### 3.2.2 后端架构

**分层架构**:
```
Controller (控制器层)
    ↓ 请求路由、参数校验、响应封装
Service (服务层)
    ↓ 业务逻辑、事务控制、权限验证
DAO (数据访问层)
    ↓ CRUD操作、SQL封装、数据映射
Entity (实体层)
    ↓ ORM模型、数据结构定义
Database (数据库)
    ↓ MySQL(持久化) + Redis(缓存)
```

**核心组件**:
- **FastAPI**: 高性能Web框架,自动生成OpenAPI文档
- **SQLAlchemy 2.0**: 异步ORM,支持MySQL和PostgreSQL
- **Pydantic**: 数据校验和序列化
- **PyJWT**: JWT Token生成和验证
- **Redis**: 缓存、会话存储
- **APScheduler**: 定时任务调度
- **Loguru**: 日志记录

#### 3.2.3 前端架构

**MVVM架构**:
```
View (视图层)
    ↓ Vue 3 组件、Element Plus UI
ViewModel (视图模型层)
    ↓ Composition API、响应式数据
Model (模型层)
    ↓ Pinia状态管理、API请求
```

**核心技术**:
- **Vue 3**: 组合式API、响应式系统
- **TypeScript**: 类型安全
- **Element Plus**: UI组件库
- **Pinia**: 状态管理
- **Vue Router**: 路由管理
- **Axios**: HTTP客户端
- **AntV X6**: 拓扑图编辑器
- **ECharts**: 数据可视化

### 3.4 技术栈对比

#### 3.4.1 后端框架对比

| 框架 | 优势 | 劣势 | 选型理由 |
|------|------|------|----------|
| **FastAPI** ✅ | 高性能、异步支持、自动文档、类型安全 | 生态相对年轻 | 性能优秀、开发体验好、适合高并发场景 |
| Flask | 轻量灵活、生态成熟 | 同步阻塞、缺少异步支持 | 性能不足以支撑高并发仿真场景 |
| Django | 功能全面、ORM强大 | 重量级、异步支持不完善 | 框架过重,对异步支持不如FastAPI |
| Tornado | 异步高性能 | 编程复杂度高 | 开发效率低,生态不如FastAPI |

#### 3.4.2 前端框架对比

| 框架 | 优势 | 劣势 | 选型理由 |
|------|------|------|----------|
| **Vue 3** ✅ | 响应式系统、组合式API、TypeScript支持好 | 生态相对React小 | 学习曲线平缓、开发效率高、适合中大型项目 |
| React | 生态最大、组件丰富 | 学习曲线陡峭、状态管理复杂 | 团队更熟悉Vue,React学习成本高 |
| Angular | 企业级框架、TypeScript原生 | 框架过重、学习难度大 | 过度工程化,不适合中型团队 |

#### 3.4.3 数据库对比

| 数据库 | 优势 | 劣势 | 选型理由 |
|--------|------|------|----------|
| **MySQL 8.0** ✅ | 成熟稳定、JSON支持、事务完善 | 横向扩展能力弱 | 满足ACID要求、JSON字段支持拓扑数据存储 |
| PostgreSQL | 功能最强、扩展性好 | 运维复杂度略高 | 备选方案,系统已适配 |
| MongoDB | 灵活Schema、横向扩展好 | 无事务(早期)、ACID弱 | 拓扑数据需ACID保证,不适合 |

### 4.3 多总线混合设计仿真功能

#### 4.3.1 拓扑设计器

**功能描述**:
基于AntV X6实现的图形化拓扑编辑器,支持设备节点拖拽、总线连线、布局优化等功能。

**核心能力**:
1. **设备节点操作**:
   - 从设备库拖拽设备到画布
   - 节点选中、移动、删除
   - 节点属性配置(名称、参数)
   - 节点样式自定义(图标、颜色、尺寸)

2. **总线连线**:
   - 从源端口拖拽连线到目标端口
   - 连线类型配置(LAN/RS422/RS485/CAN/1553B)
   - 连线样式区分(不同协议不同颜色)
   - 连线属性配置(协议参数、带宽限制)

3. **布局管理**:
   - 自动布局: 树形布局、层次布局、力导向布局
   - 手动布局: 拖拽调整节点位置
   - 网格对齐: 节点自动对齐到网格
   - 缩放平移: 画布缩放、平移操作

4. **拓扑验证**:
   - **环路检测**: 检测总线连接是否形成环路
   - **多连检测**: 检测一个端口是否连接多条总线
   - **带宽冲突**: 检测总线带宽是否超出设备端口限制
   - **协议匹配**: 检测连接两端的协议类型是否一致

5. **导入导出**:
   - 导出拓扑图为PNG/SVG图片
   - 导出拓扑配置为JSON文件
   - 导入JSON配置恢复拓扑

#### 4.3.2 仿真引擎

**架构设计**:
```
┌─────────────────────────────────────┐
│         仿真控制器                   │
│  (Simulation Controller)            │
└─────────────────────────────────────┘
              ↓
┌─────────────────────────────────────┐
│         仿真会话管理                 │
│  - 会话创建/启动/停止                │
│  - 状态机管理                       │
└─────────────────────────────────────┘
              ↓
┌──────────────┬──────────────────────┐
│  报文生成器   │  报文处理引擎        │
│  - 按周期生成 │  - 报文路由          │
│  - 数据注入   │  - 协议解析          │
└──────────────┴──────────────────────┘
              ↓
┌─────────────────────────────────────┐
│         数据采集与分析               │
│  - 报文记录                         │
│  - 带宽统计                         │
│  - 告警检测                         │
└─────────────────────────────────────┘
              ↓
┌─────────────────────────────────────┐
│         数据持久化                   │
│  - 报文表                           │
│  - 带宽表                           │
│  - 告警表                           │
└─────────────────────────────────────┘
```

**核心功能**:

1. **仿真会话管理**:
   - 基于工程版本创建仿真会话
   - 会话状态: `created` → `running` → `stopped`
   - 支持暂停/恢复仿真
   - 会话结束后保存仿真数据

2. **报文生成与路由**:
   - 根据协议配置的传输频率(10ms/20ms/100ms等)周期性生成报文
   - 根据拓扑连线关系路由报文
   - 模拟报文传输延迟
   - 支持手动注入测试报文

3. **带宽分析**:
   - 统计每个端口的收发带宽(bps)
   - 计算带宽利用率(实际带宽/端口速率)
   - 绘制带宽曲线图
   - 告警带宽溢出(利用率>80%)

4. **告警检测**:
   - **环路告警**: 检测报文在拓扑中循环传输
   - **多连告警**: 检测一个端口同时连接多条总线
   - **带宽溢出告警**: 端口带宽超出限制
   - **报文丢失告警**: 目标设备未收到预期报文

5. **数据注入**:
   - 手动注入自定义报文
   - 选择发送节点、接收节点、协议类型
   - 配置报文内容(字段值)
   - 观察系统响应

@router.post("/api/project", summary="创建工程")

**Service层**:
- 职责: 业务逻辑处理,事务控制,权限验证
- 示例:
```python
class ProjectService:
    async def create_project(
        self, project: ProjectCreateRequest, user: User
    ) -> Project:
        # 权限验证
        check_permission(user, "project:project:add")
        
        # 业务逻辑
        db_project = Project(**project.dict(), create_by=user.user_name)
        
        # 数据持久化
        await project_dao.insert(db_project)
        
        # 操作日志
        await log_service.record_operlog(
            title="工程管理", business_type=1, method="create_project"
        )
        
        return db_project
```

**DAO层**:
- 职责: 数据库CRUD操作,SQL封装
- 示例:
```python
class ProjectDAO:
    async def insert(self, project: Project) -> Project:
        async with get_db_session() as session:
            session.add(project)
            await session.commit()
            await session.refresh(project)
            return project
    
    async def select_by_id(self, project_id: int) -> Project:
        async with get_db_session() as session:
            result = await session.execute(
                select(Project).where(Project.project_id == project_id)
            )
            return result.scalar_one_or_none()
```

#### 5.2.2 性能优化策略

**后端优化**:
1. **数据库优化**:
   - 为高频查询字段添加索引
   - 使用Explain分析慢SQL
   - 分页查询大数据量
   - 使用JSON字段存储非结构化数据(拓扑)

2. **缓存策略**:
   - Redis缓存字典数据(TTL: 24h)
   - Redis缓存用户权限(TTL: 1h)
   - 本地缓存热点数据(进程内缓存)

3. **异步处理**:
   - 所有数据库操作使用async/await
   - 使用异步连接池复用连接
   - 长时间任务(导出、仿真)使用后台任务

4. **并发控制**:
   - 使用信号量限制并发数
   - 数据库连接池大小: 20
   - Redis连接池大小: 10

**前端优化**:
1. **代码分割**:
   - 路由懒加载: 按页面分割代码
   - 组件异步加载: 大组件异步导入
   - 第三方库分离: vendor单独打包

2. **资源优化**:
   - 图片压缩: 使用WebP格式
   - Gzip压缩: 压缩JS/CSS
   - CDN加速: 静态资源使用CDN

3. **渲染优化**:
   - 虚拟滚动: 大数据量列表使用虚拟滚动
   - 防抖节流: 输入搜索使用防抖
   - 懒加载: 图片懒加载

4. **网络优化**:
   - HTTP/2: 复用连接
   - 请求合并: 批量查询接口
   - 预加载: 提前加载关键资源
