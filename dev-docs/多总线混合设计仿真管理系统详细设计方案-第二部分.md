## 六、业务逻辑设计

### 6.1 协议管理模块

#### 6.1.1 模块概述

协议管理模块负责管理系统支持的各类通信协议,包括以太网(LAN)、RS422、RS485、CAN、1553B等协议类型的定义、配置和模板化管理。

#### 6.1.2 核心业务流程

**协议创建流程**:
```
选择协议类型 → 填写基本信息 → 配置协议参数 → 定义报文字段 
    → 设置错误处理策略 → 验证配置 → 保存协议
```

**协议应用流程**:
```
设备接口配置 → 选择协议模板 → 定制化参数 → 绑定到接口 
    → 拓扑连线验证 → 仿真执行
```

#### 6.1.3 业务规则

1. **协议创建规则**:
   - 协议名称唯一性: 同一类型下协议名称不能重复
   - 必填字段: 协议名称、协议类型必填
   - 参数完整性: 根据协议类型,必须配置对应的参数(如LAN需配置IP/端口,RS422需配置波特率)

2. **协议固化规则**:
   - 固化条件: 协议配置完整且通过验证
   - 固化后限制: 固化后的协议不可修改、不可删除
   - 固化用途: 作为标准模板,供其他项目引用

3. **协议删除规则**:
   - 引用检查: 删除前检查是否被设备接口引用
   - 固化检查: 固化的协议不可删除
   - 级联删除: 删除协议时同步删除关联的报文字段定义

4. **协议验证规则**:
   - 参数合法性: 检查IP地址格式、端口范围、波特率有效值等
   - 字段定义完整性: 报文字段的偏移量和长度不能重叠
   - 总长度校验: 所有字段长度之和不能超过协议规定的最大报文长度

#### 6.1.5 核心服务方法

```python
class ProtocolService:
    async def create_protocol(self, protocol: ProtocolCreateRequest, user: User) -> Protocol:
        """创建协议"""
        # 1. 权限验证
        check_permission(user, "protocol:add")
        
        # 2. 名称唯一性校验
        existing = await protocol_dao.select_by_name(protocol.protocol_name)
        if existing:
            raise BusinessException("协议名称已存在")
        
        # 3. 参数验证
        validate_protocol_config(protocol.protocol_type, protocol.protocol_config)
        
        # 4. 创建协议
        db_protocol = Protocol(**protocol.dict(), create_by=user.user_name)
        await protocol_dao.insert(db_protocol)
        
        # 5. 记录日志
        await log_service.record_operlog(
            title="协议管理", business_type=1, method="create_protocol"
        )
        
        return db_protocol
    
    async def update_protocol(self, protocol_id: int, protocol: ProtocolUpdateRequest, user: User) -> Protocol:
        """更新协议"""
        # 1. 权限验证
        check_permission(user, "protocol:edit")
        
        # 2. 查询协议
        db_protocol = await protocol_dao.select_by_id(protocol_id)
        if not db_protocol:
            raise BusinessException("协议不存在")
        
        # 3. 固化检查
        if db_protocol.is_locked:
            raise BusinessException("固化协议不可修改")
        
        # 4. 参数验证
        validate_protocol_config(protocol.protocol_type, protocol.protocol_config)
        
        # 5. 更新协议
        for key, value in protocol.dict(exclude_unset=True).items():
            setattr(db_protocol, key, value)
        db_protocol.update_by = user.user_name
        await protocol_dao.update(db_protocol)
        
        # 6. 清除缓存
        await cache_service.delete(f"protocol:{protocol_id}")
        
        return db_protocol
    
    async def delete_protocol(self, protocol_id: int, user: User):
        """删除协议"""
        # 1. 权限验证
        check_permission(user, "protocol:remove")
        
        # 2. 查询协议
        db_protocol = await protocol_dao.select_by_id(protocol_id)
        if not db_protocol:
            raise BusinessException("协议不存在")
        
        # 3. 固化检查
        if db_protocol.is_locked:
            raise BusinessException("固化协议不可删除")
        
        # 4. 引用检查
        ref_count = await device_interface_dao.count_by_protocol_id(protocol_id)
        if ref_count > 0:
            raise BusinessException(f"协议被{ref_count}个设备接口引用,无法删除")
        
        # 5. 逻辑删除
        await protocol_dao.delete(protocol_id)
        
        # 6. 清除缓存
        await cache_service.delete(f"protocol:{protocol_id}")
    
    async def lock_protocol(self, protocol_id: int, user: User) -> Protocol:
        """固化协议"""
        # 1. 权限验证
        check_permission(user, "protocol:edit")
        
        # 2. 查询协议
        db_protocol = await protocol_dao.select_by_id(protocol_id)
        if not db_protocol:
            raise BusinessException("协议不存在")
        
        # 3. 配置验证
        if not db_protocol.protocol_config:
            raise BusinessException("协议配置不完整,无法固化")
        
        # 4. 固化
        db_protocol.is_locked = True
        db_protocol.update_by = user.user_name
        await protocol_dao.update(db_protocol)
        
        return db_protocol
```

### 6.2 设备管理模块

#### 6.2.1 模块概述

设备管理模块负责管理系统中的设备分类、设备模型和设备接口配置,为拓扑设计提供设备节点的基础数据。

#### 6.2.2 核心业务流程

**设备创建流程**:
```
创建设备分类 → 创建设备 → 配置设备基本信息 → 添加设备接口 
    → 配置接口参数 → 绑定协议模板 → 配置报文 → 保存设备
```

**设备应用流程**:
```
拓扑设计器 → 从设备库选择设备 → 拖拽到画布 → 创建设备实例 
    → 配置实例参数 → 连线到其他设备 → 保存拓扑
```

#### 6.2.3 业务规则

1. **设备分类规则**:
   - 分类名称唯一性
   - 删除分类前需清空分类下的设备

2. **设备创建规则**:
   - 设备名称唯一性
   - 必须关联设备分类
   - 至少配置一个接口

3. **接口配置规则**:
   - 接口名称在设备内唯一
   - 接口类型必须与协议类型匹配
   - 报文配置需关联协议模板

4. **设备删除规则**:
   - 删除前检查是否被拓扑引用
   - 级联删除设备的所有接口

### 6.3 工程管理模块

#### 6.3.1 模块概述

工程管理模块是系统的核心模块,负责项目全生命周期管理,包括工程创建、版本管理、拓扑设计和仿真功能。

#### 6.3.2 核心业务流程

**工程创建到仿真流程**:
```
创建工程 → 创建版本 → 设计拓扑(添加设备、连线) 
    → 配置设备参数 → 拓扑验证 → 版本固化 
    → 创建仿真会话 → 启动仿真 → 监控报文/带宽 
    → 分析结果 → 停止仿真 → 导出报告
```

**版本管理流程**:
```
V1.0创建 → 编辑拓扑 → V1.0固化 → 基于V1.0克隆V1.1 
    → 编辑V1.1 → V1.1固化 → 版本对比(V1.0 vs V1.1)
```

#### 6.3.3 业务规则

1. **工程创建规则**:
   - 工程名称唯一性
   - 工程编码可自动生成(时间戳+随机数)

2. **版本管理规则**:
   - 版本号格式: `主版本.次版本.修订版` (如1.0.0)
   - 版本号在工程内唯一
   - 固化后的版本不可修改、不可删除
   - 克隆版本时自动递增版本号

3. **拓扑验证规则**:
   - **环路检测**: 使用DFS算法检测拓扑中是否存在环路
   - **多连检测**: 检查一个端口是否连接多条总线
   - **协议匹配**: 检查连接两端的协议类型是否一致
   - **参数完整性**: 检查所有设备节点和连线的参数是否配置完整

4. **版本固化规则**:
   - 固化条件: 拓扑验证通过
   - 固化后: 版本状态变为`locked`,拓扑数据不可修改
   - 固化记录: 记录固化时间、固化人

```python
class ProjectService:
    async def create_project(self, project: ProjectCreateRequest, user: User) -> Project:
        """创建工程"""
        pass
    
    async def create_version(self, project_id: int, version: VersionCreateRequest, user: User) -> ProjectVersion:
        """创建版本"""
        pass
    
    async def clone_version(self, version_id: int, new_version: VersionCloneRequest, user: User) -> ProjectVersion:
        """克隆版本"""
        # 1. 查询源版本
        source_version = await version_dao.select_by_id(version_id)
        
        # 2. 查询源版本的拓扑数据
        source_topology = await topology_dao.select_by_version_id(version_id)
        
        # 3. 创建新版本
        new_version_entity = ProjectVersion(
            project_id=source_version.project_id,
            version_number=new_version.version_number,
            version_name=new_version.version_name,
            description=new_version.description,
            create_by=user.user_name
        )
        await version_dao.insert(new_version_entity)
        
        # 4. 复制拓扑数据
        if source_topology:
            new_topology = ProjectTopology(
                project_id=source_version.project_id,
                version_id=new_version_entity.version_id,
                topology_data=source_topology.topology_data,  # 深拷贝JSON
                create_by=user.user_name
            )
            await topology_dao.insert(new_topology)
        
        return new_version_entity
    
    async def lock_version(self, version_id: int, user: User) -> ProjectVersion:
        """固化版本"""
        # 1. 查询版本
        version = await version_dao.select_by_id(version_id)
        
        # 2. 查询拓扑数据
        topology = await topology_dao.select_by_version_id(version_id)
        
        # 3. 拓扑验证
        if not topology or not topology.topology_data:
            raise BusinessException("拓扑数据为空,无法固化")
        
        validation_result = await self.validate_topology(topology.topology_data)
        if not validation_result.is_valid:
            raise BusinessException(f"拓扑验证失败: {validation_result.errors}")
        
        # 4. 固化版本
        version.is_locked = True
        version.locked_time = datetime.now()
        version.locked_by = user.user_name
        await version_dao.update(version)
        
        return version
    
    async def validate_topology(self, topology_data: dict) -> ValidationResult:
        """拓扑验证"""
        errors = []
        
        # 1. 环路检测
        if self._has_cycle(topology_data):
            errors.append("拓扑中存在环路")
        
        # 2. 多连检测
        multi_connections = self._find_multi_connections(topology_data)
        if multi_connections:
            errors.append(f"以下端口存在多连: {multi_connections}")
        
        # 3. 协议匹配检测
        protocol_mismatches = self._find_protocol_mismatches(topology_data)
        if protocol_mismatches:
            errors.append(f"以下连线的协议类型不匹配: {protocol_mismatches}")
        
        return ValidationResult(is_valid=len(errors) == 0, errors=errors)
    
    def _has_cycle(self, topology_data: dict) -> bool:
        """使用DFS检测环路"""
        graph = self._build_graph(topology_data)
        visited = set()
        rec_stack = set()
        
        def dfs(node):
            visited.add(node)
            rec_stack.add(node)
            for neighbor in graph.get(node, []):
                if neighbor not in visited:
                    if dfs(neighbor):
                        return True
                elif neighbor in rec_stack:
                    return True
            rec_stack.remove(node)
            return False
        
        for node in graph.keys():
            if node not in visited:
                if dfs(node):
                    return True
        return False
```

### 6.4 系统管理模块

系统管理模块包括用户管理、角色管理、菜单管理和日志管理,为整个系统提供基础的权限控制和审计功能。

#### 6.4.1 用户管理

**核心功能**:
- 用户CRUD
- 密码重置
- 用户导入/导出
- 用户状态管理(启用/停用)

**业务规则**:
- 用户名唯一
- 密码复杂度: 至少8位,包含大小写字母和数字
- 默认密码: 从系统配置读取
- 管理员账号不可删除

#### 6.4.2 角色管理

**核心功能**:
- 角色CRUD
- 菜单权限分配
- 数据权限配置

**权限模型**:
```
角色 1-N 菜单权限
角色 1-N 数据权限
用户 N-1 角色
```

**数据权限类型**:
1. 全部数据权限: 可查看所有数据
2. 自定义数据权限: 可查看指定部门的数据
3. 本部门数据权限: 只能查看本部门数据
4. 本部门及以下数据权限: 可查看本部门及下级部门数据

#### 6.4.3 菜单管理

**菜单类型**:
- M: 目录(一级菜单)
- C: 菜单(二级菜单)
- F: 按钮(权限标识)

**菜单树结构**:
```
系统管理 (M)
├── 用户管理 (C)
│   ├── 用户查询 (F) - system:user:query
│   ├── 用户新增 (F) - system:user:add
│   ├── 用户修改 (F) - system:user:edit
│   ├── 用户删除 (F) - system:user:remove
│   └── 用户导出 (F) - system:user:export
├── 角色管理 (C)
└── 菜单管理 (C)
```

#### 6.4.4 日志管理

**操作日志**(sys_oper_log):
- 记录内容: 操作模块、操作类型、操作方法、请求参数、返回结果、操作人、操作IP、操作时间
- 操作类型: 新增、修改、删除、授权、导出、导入、强退、生成代码、清空数据
- 存储策略: 按月分区,保留12个月

**登录日志**(sys_logininfor):
- 记录内容: 用户名、登录IP、登录地点、浏览器、操作系统、登录状态、提示消息、登录时间
- 存储策略: 按月分区,保留6个月

## 七、接口设计

### 7.1 接口设计原则

#### 7.1.1 RESTful API规范

遵循RESTful架构风格,使用HTTP方法语义:
- **GET**: 查询资源
- **POST**: 创建资源
- **PUT**: 完整更新资源
- **PATCH**: 部分更新资源
- **DELETE**: 删除资源

#### 7.1.2 URL设计规范

- 使用名词复数表示资源: `/api/projects`
- 使用路径参数表示资源ID: `/api/projects/{id}`
- 使用查询参数表示过滤条件: `/api/projects?status=1&page=1`
- 层级资源使用嵌套路径: `/api/projects/{id}/versions`

#### 7.1.3 响应格式

**统一响应格式**:
```json
{
  "code": 200,            // 业务状态码
  "msg": "操作成功",       // 提示信息
  "data": {},             // 响应数据
  "timestamp": 1234567890 // 时间戳
}
```

**成功响应 (code=200)**:
```json
{
  "code": 200,
  "msg": "操作成功",
  "data": {
    "project_id": 1,
    "project_name": "项目A"

}
```

**失败响应 (code≠200)**:

### 7.2 接口安全性

#### 7.2.1 认证机制

**JWT Token认证**:
1. 用户登录成功后,服务端生成JWT Token
2. Token包含用户ID、用户名、过期时间
3. 客户端每次请求在Header中携带Token: `Authorization: Bearer {token}`
4. 服务端验证Token有效性、过期时间
5. Token过期后需重新登录

**Token结构**:
```
Header.Payload.Signature
```

**Payload内容**:
```json
{
  "user_id": 1,
  "user_name": "admin",
  "exp": 1234567890  // 过期时间戳
}
```

#### 7.2.2 授权机制

**RBAC权限控制**:
1. 用户关联角色
2. 角色关联菜单权限(perms)
3. 后端接口使用装饰器验证权限

**权限验证装饰器**:
```python
@router.post("/api/project")
@require_permission("project:project:add")  # 权限标识
async def create_project():
    pass
```

#### 7.2.3 数据加密

- 密码存储: Bcrypt加密
- 敏感数据传输: HTTPS加密
- Token签名: HMAC-SHA256
