# 用户、角色写接口请求契约收敛

日期：2026-10-16。本轮已完成，未提交或发布。

## 最终行为

八类写操作使用独立 Pydantic 请求模型，拒绝操作范围之外的字段，并在持久化服务再次按操作限制可写字段。个人资料绑定当前登录用户；客户端不能通过资料入口修改身份、部门、状态、密码、删除标记或角色、岗位关联，也不会把登录时的旧关联快照回写。

| 入口 | 允许的业务字段 |
| --- | --- |
| 个人资料 | 昵称、邮箱、手机号、性别；用户 ID 由登录身份提供。 |
| 用户普通编辑 | 必需 userId；账号、昵称、部门、联系方式、身份证、性别、状态、备注、角色、岗位。密码和头像保留专用入口。 |
| 用户新增 | 普通表单字段及必需的账号、昵称、初始密码；不接收 userId 和服务端审计字段。 |
| 用户状态 | 仅 userId、status。 |
| 角色普通编辑 | 必需 roleId；名称、权限字符、排序、状态、备注、菜单树关联设置、菜单。数据权限使用专用入口。 |
| 角色新增 | 必需名称、权限字符、排序；允许表单中的状态、备注及菜单设置。 |
| 角色状态 | 仅 roleId、status。 |
| 角色数据权限 | 必需 roleId、dataScope；可选部门树关联设置和 deptIds，不接收角色展示字段、菜单或状态。 |

roleIds、postIds、menuIds、deptIds 全链路保留字段存在性：未提供则保留原关联，空数组清空，显式 null 延续清空语义。不同关联独立处理。用户省略部门时保留原值，显式 null 清空可空部门；目标用户数据范围检查继续执行，提供非空部门时继续检查部门范围。

复用 FastAPI/Pydantic 的请求校验、既有领域校验和 Problem Details，越界字段、缺失必需字段、无效枚举及不可空字段的显式 null 返回 422。既有邮箱等领域校验在进入审计包装前完成，避免变成 500。前端沿用当前错误反馈，每次失败只呈现一次；未新增反馈或异常体系。

后端保留内部命令模型，HTTP 输入经 `exclude_unset=True` 转换后再注入服务端身份与审计字段；前端三个用户/角色编辑组件改为显式组装请求，个人资料已有四字段模式继续复用。OpenAPI 与生成类型同步，六个路径的八个写操作发生变化；其他路径和已有响应模型无漂移，重新生成五个产物后内容完全一致。

选择直接采用现有 [Pydantic extra='forbid'](https://docs.pydantic.dev/latest/api/config/#pydantic.config.ConfigDict.extra) 和 [FastAPI 的 exclude_unset 更新方式](https://fastapi.tiangolo.com/tutorial/body-updates/#using-pydantics-exclude_unset-parameter)，并核对 [Pydantic 源码](https://github.com/pydantic/pydantic/blob/main/pydantic/main.py)。代价是明确维护八类领域输入；收益是运行时校验、OpenAPI 和前端类型来自同一契约，无需新增框架或通用字段过滤设施。本轮责任位于业务请求及写入层，未修改 ZXUI 库实现。

真实链路验证同时确认并修复两个必要调用问题：部分用户编辑经过 CQRS 统一校验时不再要求未提供的账号；角色管理详情允许读取禁用角色，禁用后响应回读和再次启用可完成，登录授权的启用状态筛选及软删除过滤保留。登录时间、IP 的内部更新改用专门的 login 操作类型，避免收紧 status 白名单后丢失登录记录。

真实业务验证 **23 组通过，0 个未处理拒绝**。生产 API/HTTP、四个生产 SFC 的 setup/提交路径及 ZXUI 源码 hooks，通过真实 Axios XHR 调用本机 FastAPI/MySQL：

- 普通编辑保留未提供关联，关联可独立替换、清空；数据范围切换且省略部门时仍保留原部门关联。
- 用户、角色状态只改变状态；禁用角色仍可管理读取及重新启用，原关联保留。
- 八类入口逐字段拒绝越界写入，均为真实 422 Problem Details、保留错误上下文且反馈一次；拒绝后数据库业务状态不变。另验证 11 类必需字段错误及 5 类原有领域校验错误。
- 用户表单、角色表单、数据权限抽屉及个人资料组件真实提交成功，不发送审计字段、内部 type 或其他操作字段。
- 普通用户登录后，管理员改变其角色/岗位，再保存个人资料，新的关联保持；尝试修改自身权限或他人身份均被拒绝，原密码仍可登录。
- 仅本人数据范围的用户可以省略部门完成合法部分编辑，编辑另一用户仍被原有数据范围检查拒绝。该既有异常为 HTTP 401、errorCode 30010，本轮保留其状态和恢复反馈，未混入 401/403 分类调整。
- 临时两名用户、三个角色、两个岗位、两个部门按现有接口清理，最终业务列表字段及总数与管理员登录后采集的基线逐项一致。早期探针受现有限流中断后，已核对并清理仅属探针的差集记录，最终探针放慢写请求节奏，未调整限流配置。

以上覆盖真实网络、业务读写和组件提交决策；原生表单校验、树及弹层视觉交互未在浏览器验收，未使用 computer use。业务删除、登录和审计仍产生正常的开发库记录，不声称物理回滚数据库。仅停止本轮启动的后端，保留原有 Docker MySQL、Redis 及其他服务。
