# 详情缺失契约与编辑身份保护

日期：2026-10-16。本轮已完成，未提交或发布。

## 最终行为

带 ID 的详情读取不再把不存在的资源包装成空成功响应。后端复用 `ResourceNotFoundException`、既有领域错误码及全局 AppException / Problem Details 处理；前端只接受 ID 存在且匹配请求目标的详情，防止编辑落入新增分支。

| 责任边界 | 本轮变化 |
| --- | --- |
| 系统详情 | 参数、字典类型、字典数据、部门、角色、菜单、岗位、公告的 detail service 返回真实资源或抛 404；移除随之失效的空模型检查及 query handler 的空成功 fallback。 |
| 其他同类详情 | 工程、工程版本、协议、定时任务和代码生成表详情同样进入现有 404 管线。移除对应 controller 的空对象 fallback。仓储 `find_by_id -> None` 契约不变。 |
| 旧详情缓存 | 角色、部门、菜单的缓存命中须有匹配 ID；旧空模型或错 ID 缓存删除后回源。缺失详情不再写空对象。没有新增缓存机制。 |
| 权限与事务 | 角色、部门仍先做原有数据权限检查。无权访问可能先返回 403，不为统一 404 而提前越权读取。原有事务装饰保留。 |
| 前端 API | `src/api/detail.ts` 的 `requestDetail` 仅供显式单资源读取，接入 17 个真实入口：系统八类、用户、工程两个入口、版本、协议、设备、设备分类、任务和生成器。用户校验 `data.userId`，生成器校验 `info.tableId`，设备分类使用真实字段 `deviceCategoryId`。 |
| 身份错误 | 接受数值路由字符串；响应 ID 必须为正的安全整数且匹配目标。错误 200 抛本地 `DetailIdentityError`，不伪造服务器 404。真实 HTTP 错误原样保留 cause、config、response。 |
| 反馈 | 显式详情读取默认复用既有 HTTP 错误反馈；GET 没有成功反馈 key，不新增成功提示。`silentError` 仍交由当前编辑操作呈现，过期读取保持静默。身份错误反馈受既有旁路隔离保护。 |
| 编辑终点 | 五类既有读取 helper 和用户编辑会保持失败状态、阻止确认。协议只补本轮必要的读取成功与编辑目标保存闸门；岗位、字典数据和协议父事件承接已反馈的拒绝。未扩展为其他编辑入口的完整生命周期改造。 |

合法空结果保留：`getUser(undefined)` / 空串仍读取新增选项，允许 `data=null`；列表、树、字典集合和选项集合继续允许为空，不进入详情身份校验。拓扑等具有自身空结果语义的接口未套用这个规则。

选择沿用现有异常、业务请求封装及反馈策略，代价是为详情入口明确登记 ID 字段；HTTP 通用库无法判断领域资源身份，因此 ZXUI、依赖和 vendor 包均未修改。本轮没有拆分 DTO、调整日志、重试或引入查询框架。404 语义参考 [RFC 9110 §15.5.5](https://www.rfc-editor.org/rfc/rfc9110.html#section-15.5.5)。
