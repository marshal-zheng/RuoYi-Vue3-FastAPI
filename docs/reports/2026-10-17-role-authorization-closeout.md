## 本次发现并补齐

已提交前端以 JSON 数组执行双向授权，但基线后端仍使用 query 参数和旧字符串 DTO。正确写链路此前仅存在于保留的未提交源改动。真正 FastAPI HTTP 回归先复现：用户侧保存/清空返回 422，角色侧批量操作表面返回 204、实际忽略 JSON；因此原浏览器及源目录通过，不能证明干净 `std` 可独立闭环。

本次只补交付四个固定授权 DTO、commands/handlers、`UserRoleService`、生产 DI 和四个 PUT 入口。用户侧完整替换及显式清空、角色侧增量授予与定向撤销保持已确认契约。存在性、root 保护、双向数据范围及被移除关联均在写入前预检，事务覆盖整个操作。授权拒绝使用 403；删除无消费者的旧字符串 DTO、UserService 授权写方法、旧读取辅助及对应 ports，没有增加兼容入口或结果缓存。

`shared/openapi.json` 仅同步四个授权 PUT、四个新 DTO schema，并删除旧 Crud schema；其他 JSON 语义不变。既有 generated types/SDK 已包含该契约，无需整库重新生成。普通用户/角色/部门 CRUD、profile、密码及字段白名单等原未提交业务规则继续保留。

常规前端 `lint:check` 只检查 `src`；额外覆盖阶段涉及的测试后发现格式错误和三处 `any`。三个测试仅整理格式、明确状态类型并补全 modal 替身方法；转译后 AST 比较确认原运行语句和断言未改变。删除旧 DTO 所触及的用户 VO 同时做等价类型语法整理；隔离候选其余 18 个模型的完整 JSON Schema 与基线一致，源目录的原业务字段及函数另有 AST 保留证明。
