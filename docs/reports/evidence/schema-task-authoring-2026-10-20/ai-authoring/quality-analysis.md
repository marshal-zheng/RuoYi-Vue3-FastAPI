# 同一 API 下的任务文档质量对照

四次未经修改的首轮输出全部满足预先冻结的普通岗位 CRUD 功能要求：完整文档组 2/2，任务文档组 2/2。每次都通过同一个冻结评估器的 30 项检查，以及独立人工源码审查。本轮没有改评估标准、修补作者代码或重试选择答案。

| 运行 | 文档组 | API/发行声明 | 自动检查 | 人工审查 |
| --- | --- | --- | --- | --- |
| 01-baseline | 完整 README | 同一当前版本 | 30/30 | 通过 |
| 02-current | 新入口 + CRUD | 同一当前版本 | 30/30 | 通过 |
| 03-current | 新入口 + CRUD | 同一当前版本 | 30/30 | 通过 |
| 04-baseline | 完整 README | 同一当前版本 | 30/30 | 通过 |

`baseline/current` 在本轮只表示文档实验组，不能解释成旧 API 与新 API。两组共享同一个本轮发行包；其 21 份声明和 9 份 JS/CSS 文件与 oracle 使用的当前版本逐字相同，见 `checker-artifact-admission.json`。两组的任务、domain、输出格式和公开类型摘录一致。

检查覆盖真实声明类型、字段键、DTO 白名单与可信身份、非法值拒绝、原样 signal、已知与未知后端错误、原生校验、单次会话、公开 submit/reset、pending 按钮状态和响应式布局。人工另外检查真实控件 API、编辑值所有权、请求行为和固定任务遗漏。每次 `manual-review.json` 记录详细依据，`authored/` 只是 `final.json` 两个源码字段的逐字提取。汇总核对了 raw 输出、检查器输入和提取文件的哈希与内容一致。

## 功能要求一致，不等于交互方案完全相同

有两项必须保留的非评分观察：

- 完整文档组两次都用 `ZxSelect` 表达 status；任务文档组两次都用 `ZxInput` 加枚举校验。固定任务只要求 status 为 `'0' | '1'`，没有规定选择控件，因此不能事后把任务组判为失败；但不能据此宣称两组的使用体验或控件选择完全相同。
- 03-current 使用任务明确允许的原生 `Rule.col`，没有采用 `columns/fullWidth` 简写。它满足布局要求，却说明通过功能检查不代表作者总会采用最简公共写法。

完整参考仍保留 `ZxSelect` 资源示例，作者入口也可到达它。本次模型仅获得预选的 README + CRUD，不能继续检索；示例分布、措辞和模型波动都可能影响控件选择。两份同向样本不足以区分原因，更不能据此断言新文档删除了选择控件能力。若未来需要比较完全相同的交互质量，应在下一次调用前明确控件与交互验收约束，而不是回头修改本轮规则。

## 与实际 token 结果合并解读

完整文档组平均输入 17,327 token，任务文档组 16,545，少 782，约 4.51%。任务组平均输出从 3,796.5 增至 4,428.5；单次作者调用的 input + output 平均从 21,123.5 降至 20,973.5，只少 150，约 0.71%。两对总量差分别为 -390 和 +90，不能称为稳定的总 token 节约或整体开发效率提升。

这些数据来自 `usage-summary.json` 的真实调用 usage。reasoning 已包含在 output 中，不能重复相加。成本范围仅为四次受控代码作者调用，不含工程修改文档、独立质量检查、人工审阅代理、实际检索或路由成本；不是整个开发过程的总消耗。

本轮可确认的局部结果是：在这一个预选普通 CRUD 任务中，任务资料减少了输入上下文，固定功能要求的首轮通过率没有下降。它尚未证明更低的返工、更快生成、交互体验等价、复杂业务成功率或稳定总 token 收益。

## 文档能力保留与验证范围

独立覆盖审查见上级目录 `coverage-review.md/json`：完整参考保留了旧 README 的全部行为正文，复杂任务有明确组合入口，18 类能力都有映射。两项初稿准确性问题已在模型调用前修正。发行包另验证了文档链接与原始 recipe 的交付，没有增加 AI 专用 DSL、运行时机制或第二套示例实现。

质量评估使用真实发行声明运行 vue-tsc，执行 DTO/错误映射及原生 async-validator，在 Happy DOM 中以公共 SchemaForm API stub 验证宿主接线。没有执行浏览器或完整引擎交互，不能把本次 30/30 检查数解释为通用企业级质量百分比。保留清晰的能力入口和完整参考有长期维护价值；是否继续压缩某个任务材料，应由真实任务与质量约束决定，而不是以 token 数为由删掉复杂能力或放宽验收。
