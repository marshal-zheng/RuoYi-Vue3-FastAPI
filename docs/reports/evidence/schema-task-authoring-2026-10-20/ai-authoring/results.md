## 可得出的结论与边界

1. 本任务的给定输入减少了 4.51%，但输出和推理增长抵消大部分减少。总量配对方向不一致，不能把 −0.71% 的均值描述成稳定节省；耗时也没有改善。
2. 处理因素是作者文档的组合与内容，包含组织、长度及通用 DTO / 生命周期指导变化。不能拆分为各自独立因果，也不能把推理随机波动归因为某个文档设计。
3. B 的 README 导航已计入输入，但 CRUD 路径由实验预先指定。无工具条件没有测量自动检索、选路或沿链接读取成本，因此不能推广为完整 AI 开发流程的 token 收益。
4. 只有一个普通 CRUD 任务、每组两次重复。ABBA 缓和顺序影响，但无法排除模型随机性和服务调度影响；没有证明复杂明细、联动、异步资源、多模型或长期开发流程的稳定收益。
5. 本轮 API、类型和发行包相同，只能用于比较这两套材料。不能与上一轮旧 / 新 API 对照拼接成累计改善比例。

任务文档在本样本中保留了功能验收结果，但“文档更短”不能直接等同于“整体 AI 更省 token”。后续若需要更强的效率结论，应在真实新增复杂业务任务中继续收集质量、检索与修改回合成本，避免仅为得到有利数字而重跑本样本。
