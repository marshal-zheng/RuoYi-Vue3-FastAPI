# Schema AI 作者质量对照

本次固定岗位 CRUD 任务中，旧版和当前版各两次未经修补的首轮输出均通过：真实版本公开声明、领域行为、原生验证、内存组件接线及人工源码审查。没有发现作者缺陷，没有修补生成代码，没有重试选择答案。

| 运行 | 原评估器 | 统一修正版 | 人工审查 | 作者修补 |
| --- | --- | --- | --- | --- |
| 01-baseline | 29/30，布局误报 | 30/30 | 通过 | 0 |
| 02-current | 30/30 | 30/30 | 通过 | 0 |
| 03-current | 30/30 | 30/30 | 通过 | 0 |
| 04-baseline | 29/30，布局误报 | 30/30 | 通过 | 0 |

这里的检查数是定位依据，不是通用质量评分。两个旧版误报来自评估器错误地把 `col={span:24,md:12}` 的大屏宽度退回 `span:24`；实际 Element Plus CSS 是 `min-width:992px`，`md:12` 在更宽屏幕持续生效。原始评估器和结果保留，v2 只修正断点累计语义，并在旧两份合法 oracle、错误 oracle及新增 md-only oracle上验证，然后统一应用于四次输出。依据、时间、差异及哈希见 `checker/freeze-v2.json`。CLI 实验功能启动警告的工具分类误报由另一个独立协议审计处理；它不是作者行为。

每个 `runs/<id>/manual-review.json` 记录源码审查结论；`authored/` 是 `final.json` 源码字段的逐字提取。汇总核对了原始输出哈希、评估器读取源码哈希和提取文件内容一致。机器可读结果见 `quality-summary.json`。

两种公开契约都能完成此固定任务。旧版生成代码正确处理宽 `Values` 和非泛型 ref/save，并逐字段声明原生布局；新版正确使用泛型、集中 `columns`、`fullWidth` 和分段错误路径。新版没有在本样本中提高首轮通过率，因为两边已经各 2/2。领域校验、DTO 白名单及记录身份隔离在两边仍由业务负责，不能为减少作者代码而搬进组件库。

验证范围有明确边界：使用各自真实发行声明运行 `vue-tsc`，运行 DTO/错误映射/原生 `async-validator`，在 Happy DOM 中以公开 SchemaForm API stub 验证宿主接线。人工另核对真实 ZXUI 控件能力、单一编辑值 owner、初始化寿命和请求行为。本对照没有执行浏览器、完整表单引擎交互或复杂明细场景，不能据此推断复杂企业业务的一般成功率。

长期 AI 优化的优先级：

1. **先优化按任务取用的公共资料。** 本次喂入完整 README，新版资料包含更多复杂能力，输入增加；这衡量的是现有入门资料与 API 的合并成本。为普通 CRUD、复合字段和独立配置面板提供明确的短入口，指向既有规范与已交付 recipe，让作者只加载相关部分。收益是减少无关上下文及错误套用；完整架构文档仍然保留。是否实际省 token，需要另一个预先冻结的对照验证。
2. **继续保持可编译的公开契约与单一 owner。** 两份新版输出都正确使用公开泛型、布局和错误路径，这证明当前接口可被作者消费；本样本尚不能证明它减少了返工。示例与真实声明共同检查，比再增加一套 AI 专用 schema DSL、别名或兼容路径更有维护收益。
3. **在新增真实能力时补一个代表性作者样本。** 优先选择明细行身份与错误、复合字段 raw/blocking、异步上传这类已有真实需求，复用本次原样源码与质量门槛方法，不扩成庞大的基准设施。以首轮可用、实际返工和总 token 为目标，避免用源码行数或单次推理 token 波动替代证据。

实际 token 结果由 `usage-summary.json` 和总结果报告给出。这里不把代码更短、接口更强或两次通过直接写成 token 节约。
