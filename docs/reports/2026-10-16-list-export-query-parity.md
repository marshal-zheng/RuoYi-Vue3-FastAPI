# 参数、角色、字典和操作日志的列表／Excel 条件一致性

日期：2026-10-16。本轮只处理条件一致性，未提交 Git、未发布包。

## 根因与责任

问题在业务消费者，ZXUI 已有 `getStateSnapshot`、`queryTransform`、字符串路径 `updateState` 足够解决。后端各列表和导出共用同一查询模型及 Service/Repository 过滤逻辑，无需修改库或后端。

- 参数和角色导出直接使用表单 query，绕过列表的 `serializeDateRange`。
- 字典类型导出虽取得快照，但未经过日期转换。字典数据导出又按字段拼装并回退 `defaultDictType`，可能和当前选择的类型分叉。
- 操作日志的 loader 仍按旧的平铺参数读取日期和分页，筛选／排序仍给 `updateState` 传对象，导出调用 GridList 已无的 `getCurrentQuery` 后退回空条件。其工程管理消费者依赖初始 `query.title` 限制模块，旧导出会丢失它。

依据：五个修改的 Vue 文件、对应 `src/api`、ZXUI `grid-list/src/{grid-list.vue,use-grid-state.ts,use-grid-request.ts}`，后端 `modules/system/api/{config,role,dict,log}_controller.py` 及相关查询模型和 Service/Repository。库先克隆 query 再转换，快照保留可编辑条件；无需增加旁路缓存或新查询管理器。

## 实现

1. 参数、角色、字典类型的导出直接读取 GridList 快照，复用列表同一 `queryTransform → serializeDateRange`。日期条件仅转换请求副本。
2. 字典数据列表与导出都使用当前 `query`，导出不再回退路由初始类型。默认类型仍按原流程用于页面初始化和其他业务用途。
3. 角色、字典数据和操作日志 loader 显式将 `query/pager` 转成 API 筛选及 `page/pageSize`，导出只传筛选。
4. 操作日志使用公开字符串状态路径更新条件，筛选／搜索／排序重置第 1 页；清除排序删除排序条件。排序方向按后端契约保留 `ascending/descending`。
5. 移除无真实消费者的 `getCurrentQuery` 旧调用及旧暴露接口。普通操作日志和工程管理日志继续共用组件，模块条件保留在 GridList 中。

长期收益来自消除多份条件和请求结构歧义，复用现有公开契约；代价是调整五个业务消费者并增加一份聚焦回归。未引入依赖或兼容层，未混入下载、重试、日志副作用隔离或列表错误处理优化。

## 实测发现的范围外限制

- 字典数据 Repository 仅按 `dict_sort` 排序。跨类型且每页 1 条时，排序相同的记录存在分页重复、漏项，已在真实请求中观察到。本轮未更改后端排序；类型清空条件的验收使用单页 84 条集合比对，字典数据跨页验收使用选定类型的 2 条记录。不能将这次通过表述成任意排序分页已稳定。
- 后端既有非分页导出上限为 10000 条，本轮未改变；实际验证数据均低于上限。
- 工程管理模块当前无日志，真实验证覆盖其空结果和模块条件保留；有数据的组合筛选和排序使用现有用户管理日志验证，未为此伪造日志。

验证未新增领域数据；只产生正常登录／导出审计记录。验证会话已退出，临时 Excel 二进制已删除；仅停止本轮启动的后端，保留原有 Docker/Redis 服务。
