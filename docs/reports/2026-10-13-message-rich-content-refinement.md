# Message 富内容层级复查

用户反馈：两行文件信息与操作、关闭并排，视觉层级杂乱。上一轮的几何/可读性验证不等于这类内容的组织已经理想。

## 判定与契约

原验证消息把标题、文件信息一起塞在 default 插槽，库只知道一块任意内容，无法安全判断其中哪一行是补充信息。
ZXUI 补充一个可选 `description` 属性/插槽，由组件统一提供富消息的层级与操作布局；业务选择内容的语义，不另写布局 CSS。

- `message` / default：主信息。存在描述时强调文字。
- `description` / 同名插槽：补充信息，支持字符串、VNode、渲染函数、TSX，插槽优先。
- 图标、主信息、关闭：固定首行。
- 描述、action：第二行左说明、右操作；标准操作为轻按钮，任意操作插槽共享位置并保留调用方控件外观。空间不足时操作换行，仍保持靠右。
- 不增加弹框式分隔线或额外 footer 留白。无描述的消息保留原来的紧凑行内操作。
- API 复用同一展示组件，不改定位、计时、主题归属或业务发送端。带描述的消息保持独立实例，防止相同主消息的不同说明被分组合并。

参考 [Fluent Toast](https://fluent2.microsoft.design/components/web/react/core/toast/usage) 的主信息与补充信息分工，以及 [Radix Toast](https://www.radix-ui.com/primitives/docs/components/toast) 的 Title / Description / Action 独立结构。具体两行布局和尺寸为本库结合现有 density 的设计选择。

中途曾尝试把操作独占第三行。用户指出它仍像从上到下罗列，最终改为固定首行及左说明/右操作的第二行；这也避免了无必要的高度增加。

## 本轮验收清单

| 场景 | 检查与证据 |
| --- | --- |
| 墨青明暗 × 三档密度 | 真实用户管理页；普通消息与 description/action 插槽；截图、颜色、尺寸、首行对齐、视口边界 |
| API 描述属性、VNode、渲染函数 | 真实发送端显示内容；slot 覆盖属性；不会把 HTML 字符串当作标签 |
| 模板组件路径 | 真实业务根应用上下文挂载展示组件；描述/操作插槽；关闭交互 |
| 操作 | slot 点击关闭；标准异步操作防重复、pending 与关闭；键盘操作 |
| 窄屏长描述 | 360px、无空格长文件名；完整换行、不裁切、按钮可达 |
| 触控 | 描述首行对齐；操作及关闭至少 44px 目标；tap 响应 |
| 不同描述的同名消息 | grouping 显式开启仍保持不同实例 |
| 普通消息 | 不增加描述留白或变更其高度、行内操作布局 |

本轮不执行业务数据写入，不新增测试文件，不运行 lint/build。浏览器验证内容不代表实际导出或服务恢复。

## 最终结果

- 最终墨青六种明暗/密度组合在已登录 `/system/user` 重新截图。普通消息为 40 / 44 / 48px，带一行描述与操作的消息为 70 / 74 / 78px。默认档由中间三行方案的 106px 降为 74px。
- 六种组合均没有消息越界或标题/描述横向溢出。图标、关闭与标题首行中心偏差为 0px；操作右边缘与首行内容右边缘一致。
- 九个主题在默认密度的明暗模式检查次级文字色，描述与浮层背景对比度最低约 6.10:1。最终布局复用这些同一语义颜色；这里不把数值验证当作完整设计或辅助技术认证。
- 字符串、VNode、渲染函数和描述插槽实际显示；插槽覆盖属性且没有调用被覆盖的渲染函数。默认转义 HTML 字符串。
- 显式开启 grouping 的同名消息，在描述不同的情况下仍为两个独立实例。
- 编译后的 Vue 模板在业务根应用上下文渲染，实际出现 header/detail 结构，操作插槽点击后关闭。
- 标准异步操作双击只调用一次，执行中 disabled / aria-busy 生效，成功关闭。最终结构中 Shift+Tab 可到操作和关闭，焦点环可见，Enter 触发操作关闭。
- 360px 窄屏、连续无分隔长文件名完整换行，消息为 328px 宽并保持两侧 16px 边距，操作自动换行且继续靠右。富消息高度由内容决定，没有固定正文最小高度。
- 已登录触控视口 360px、DPR 2 复验：操作 74 × 44px、关闭 44 × 44px，tap 仅响应一次；首行结构完整。

既有两个 feedback 测试文件的 7 项检查通过。变更 TS 模块在显式 Vue SFC 导入 shim 下定向诊断为 0（普通 TypeScript 不能直接解析 `.vue`，不代表完整 vue-tsc 检查）；结构 CSS 解析与 docs 示例模板编译通过，相关 `git diff --check` 通过。

没有增加业务视觉覆盖、额外消息管理器或新布局配置开关，Provider/Hook 继续复用既有外观、主题与 density 配置。业务发送端可直接使用新增描述契约。
