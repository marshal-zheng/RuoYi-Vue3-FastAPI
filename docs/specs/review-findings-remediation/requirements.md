# 中间件安全加固与分类删除校验 需求规格

## 简介
本规格用于修复近期评审发现的关键安全与一致性问题，范围覆盖幂等中间件、限流中间件与设备分类删除流程，并补齐必要的测试。目标是在不改变现有业务语义的前提下，消除跨用户响应重放、伪造来源绕过限流及删除引用不一致的问题。

## 需求列表

### R1: 幂等响应缓存必须按用户/会话隔离
**用户故事:** 作为系统管理员，我希望幂等缓存不会跨用户复用，以便防止敏感响应被错误重放。
**验收标准 (EARS):**
- R1.AC1: WHEN 请求携带 `X-Idempotency-Key` 且可解析出用户身份或会话标识 THEN 幂等缓存的作用域必须包含该身份标识（例如 `user_id` 或 `session_id`）。
- R1.AC2: IF 无法解析用户身份 THEN 幂等缓存必须落入匿名作用域且不得与已认证用户共享缓存。

### R2: 限流必须仅信任可信代理的转发地址
**用户故事:** 作为平台运维，我希望限流基于真实客户端地址，以便避免伪造头绕过限流。
**验收标准 (EARS):**
- R2.AC1: WHEN 请求包含 `X-Forwarded-For` THEN 系统必须仅在请求来源属于可信代理列表时才使用该头。
- R2.AC2: IF 请求来源不可信 THEN 必须使用 `scope.client` 作为限流 IP 标识。

### R3: 幂等中间件需要请求体上限保护
**用户故事:** 作为系统管理员，我希望幂等处理中不会因为超大请求体导致内存放大，以便降低 DoS 风险。
**验收标准 (EARS):**
- R3.AC1: WHEN 请求体超过可配置的最大阈值 THEN 幂等中间件必须跳过缓存逻辑并继续请求处理。
- R3.AC2: WHEN 触发超限跳过 THEN 必须记录可检索的告警或日志事件。

### R4: 删除设备分类前必须校验引用
**用户故事:** 作为业务管理员，我希望删除设备分类时不会破坏设备数据一致性，以便避免悬挂引用。
**验收标准 (EARS):**
- R4.AC1: WHEN 设备分类仍被任一设备引用 THEN 删除请求必须失败并返回明确的业务错误。
- R4.AC2: WHEN 分类无引用 THEN 删除流程应保持现有行为不变。

### R5: 新增行为必须具备单元测试覆盖
**用户故事:** 作为研发人员，我希望关键安全行为有自动化测试，以便防止回归。
**验收标准 (EARS):**
- R5.AC1: WHEN 幂等缓存按用户隔离实现完成 THEN 必须新增单元测试覆盖跨用户重放场景。
- R5.AC2: WHEN 限流可信代理逻辑实现完成 THEN 必须新增单元测试覆盖伪造 `X-Forwarded-For` 场景。
- R5.AC3: WHEN 分类删除引用校验实现完成 THEN 必须新增单元测试覆盖被引用与未被引用两种路径。
