## 目标、术语与范围

### 成功标准

用户选择更大的界面后，字体、图标、控件和布局空间协调变化；放大导致同屏容量下降时，系统按一致规则重排、减列或提供局部滚动，不偷偷缩字，也不让关键内容与操作被裁切。正常、可预测的换行是允许的，不承诺在相同屏幕上同时保持更大尺寸、原有信息量与全部元素位置。

| 概念 | 本需求中的含义 |
| --- | --- |
| 使用场景 | 办公与远距离使用的尺寸基准；依据任务和观看距离选择，不等同于设备名称 |
| 显示大小 | 相对于当前场景基准的个人偏好：90%、100%、110%、125% |
| 密度 | 控件内部与界面节奏的疏密，保持已有 density 职责，不替代显示大小 |
| 组件大小 | 单个控件的 size 语义及继承规则，不等同于全局比例 |
| 布局适配 | 根据真实可用宽高、内容最小尺寸与显式优先级调整排列 |
| 输入方式 | 鼠标、键盘、触屏、遥控器，可以并存，与显示大小分别处理 |
| 有效尺寸 | 应用场景、比例、密度、组件大小和交互约束后，实际供排版与计算消费的尺寸 |

“紧凑 90%”与已有 compact density 不得以同一个无说明的“紧凑”入口混用。百分比表达基准调整意图，不要求边框、圆角、命中区域下限及所有数值严格同比例变化。

### 范围分层

| 范围 | 交付要求 |
| --- | --- |
| ZXUI 通用能力 | 公开配置与继承、文字/空间/图标/组件尺寸、核心控件、浮层、尺寸消费接口和文档示例 |
| RuoYi 首条验证链 | 系统用户管理、应用外壳、筛选工具栏、表格/分页、多列表单弹框、下拉浮层及切档保留编辑状态 |
| 本 spec 的业务迁移范围 | 自有非仿真前端界面与共享组件，包括登录/资料、系统管理、设备/工程/协议/监控、生成器产物的 UI 契约及其中实际使用的表格、图表和编辑器控件；实施前形成准确清单 |
| 多终端交付 | 非仿真页面支持办公和远距离操作；展示布局限既有看板/监控/展示用途，目标环境内支持标准触控与浏览器事件遥控器；不为每个 CRUD 页面新建展示版 |

本规格为显示大小明确提出非仿真全范围；旧表单任务曾停止的设备、工程、监控、生成器模块，不因旧任务的范围调整而被悄悄遗漏。本轮仅生成规格，不启动其批量改造。仿真专用覆盖需要后续范围修订或独立 spec；只完成首条用户管理链路不能关闭本 spec，也不能宣称完整产品全部支持。

### 非目标

- 不使用全页 `transform: scale()`，不以 CSS zoom、浏览器缩放指令或仅修改字号来替代本功能。
- 不新建另一套主题系统、表单引擎、全站 DOM 字号修补脚本或每页四套尺寸样式。
- 不按年龄推断用户偏好；不按屏幕分辨率、设备像素比例或设备名称推断观看距离。
- 不新增账号偏好云同步服务；首版按当前浏览器中的账号与场景隔离保存，匿名页面有独立默认值。将来同步只作为默认来源，不覆盖本地显式选择。
- 不修改业务数据、校验语义、权限、仿真/拓扑坐标或用户文档正文，不以本特性触发库组件的大规模无关替换。
- 不以应用内 125% 代替浏览器缩放兼容或无障碍验证，不作未经验证的合规声明。

## 需求列表

### R1: 统一显示大小入口

**用户故事：**作为用户，我希望统一调大或调小界面，以适应个人阅读和操作需求。

**验收标准：**
- R1.AC1: 当用户进入显示设置时，系统应提供 90%、100%、110%、125% 四档，明确当前场景、当前档位及恢复当前场景默认值的入口；办公默认值为 100%。
- R1.AC2: 当用户切档时，系统应在当前页面生效，无需刷新、重新登录或提交表单；字号、图标、控件和布局空间共同响应。
- R1.AC3: 当字号或控件候选尺寸触及内容容纳、点击目标或视口约束时，系统应遵守对应约束，不能为了严格百分比而裁切内容或形成不可用控件。
- R1.AC4: 当用户修改显示大小时，系统应保留颜色主题、明暗、density 与组件 size 的独立语义；比例不得被多层重复相乘。

### R2: 多场景基准与主动切换

**用户故事：**作为在办公电脑、电视或大屏间切换的用户，我希望界面能适应实际距离和用途。

**验收标准：**
- R2.AC1: 当用户选择办公或远距离场景时，系统应使用明确标识的对应基准；同一百分比相对于当前场景解释，远距离基准经过目标设备和观看距离校准。
- R2.AC2: 当分辨率、窗口大小或输入设备变化时，系统应根据可用空间适配布局，不凭这些变化自动改写个人比例或将设备强制归类为远距离场景。
- R2.AC3: 当电视/大屏用于完整业务操作时，系统应保留表单编辑、表格操作、筛选、确认及返回能力；远距离场景不强制变为只读看板。
- R2.AC4: 当既有看板、监控或已有展示用途的页面进入展示布局时，应按业务指定的指标、告警和内容优先级组织信息并复用业务数据；不要求每个 CRUD 页面新增独立展示版，不以整页等比拉伸代替布局设计。

### R3: 核心 UI 尺寸协调变化

**用户故事：**作为阅读有困难的用户，我希望文字变大时，承载文字的控件也能正确容纳内容。

**验收标准：**
- R3.AC1: 当在各显示档位使用范围内页面时，字体、行高、UI 图标、padding/margin/gap、按钮、Input/Select/Textarea、复选/单选、表单项、表格行、卡片、菜单、Tabs 和分页应消费统一的有效尺寸契约。
- R3.AC2: 当出现长中文、英文、选中值、错误提示、帮助文字或多行内容时，控件应按约定扩展、换行或提供完整内容入口；关键操作、错误信息与必读字段不得只剩不可恢复的省略号。
- R3.AC3: 当使用 90% 或触屏输入时，组件应满足公开记录的文字与交互下限；边框等固定值和领域尺寸应按分类策略处理，不机械缩放所有 px。
- R3.AC4: 当办公场景保持 100% 且其他偏好相同时，现有默认尺寸基准应保持；必须修复的原有缺陷单独记录，不能把任意视觉变化混入兼容声明。

### R4: 应用外壳与共享布局适配

**用户故事：**作为小屏或低高度窗口的用户，我希望调大界面后仍能到达内容与操作。

**验收标准：**
- R4.AC1: 当 Header、Sidebar、Tags 或内容区尺寸变化时，相关偏移与可用宽高应保持一致，不出现相互覆盖、不可达空洞或由旧高度常量产生的裁切。
- R4.AC2: 当表单容器不足以容纳原列数时，共享布局应按有效最小列宽降低列数，必要时调整标签位置；保留字段顺序、整行意图、真实表单实例和校验行为。
- R4.AC3: 当工具栏、Tabs、菜单或分页空间不足时，共享规则应将内容重排、收纳或允许局部浏览；业务声明操作优先级，主要操作和必要导航仍然可达。
- R4.AC4: 当弹框或抽屉接近可用视口边界时，组件应限制边界并明确正文和操作区的滚动归属；低高度、软键盘或长错误提示下仍能到达关闭、确认及错误字段。
- R4.AC5: 当容器在临界尺寸附近变化时，布局应收敛到稳定状态，不反复折叠/展开、不产生持续测量循环；恢复空间后尊重用户原有折叠选择。

### R5: 作用域与浮层一致

**用户故事：**作为跨页面与弹框操作的用户，我希望所有浮层与发起它的界面保持相同显示大小。

**验收标准：**
- R5.AC1: 当子作用域未声明显示偏好时，应继承最近父作用域；显式覆盖时采用该作用域的确定值，而非将父子比例重复相乘。
- R5.AC2: 当打开 Select、Dropdown、日期面板、Tooltip、Dialog、MessageBox 或由作用域发起的通知时，其显示大小与主题应跟随所属作用域，即使实际挂载在 body。
- R5.AC3: 当浮层打开期间切换场景、档位或主题时，浮层尺寸与定位应更新，关闭重开后仍一致；并存作用域不得互相污染。
- R5.AC4: 当库通过程序化入口创建浮层时，公开契约应明确归属来源和缺省行为；业务不复制主题变量或靠全局 body 覆盖补齐归属。

### R6: 表格、虚拟化与第三方消费者

**用户故事：**作为处理大量数据的用户，我希望缩放后的视觉尺寸与滚动、定位和点击计算一致。

**验收标准：**
- R6.AC1: 当范围内虚拟表格或列表切档时，条目高度、表头、测量缓存和视口计算应消费相同有效尺寸，末行可达、点击行准确，阅读位置按可用行标识或邻近位置保持。
- R6.AC2: 当普通记录表空间不足时，业务可按声明的列优先级组织详情；当任务需要横向比较或编辑时，应提供表格内部滚动，不擅自隐藏关键列或压小文字。
- R6.AC3: 当 VXE、图表或富文本工具栏跟随显示设置时，应通过相应公开能力更新布局与 UI 尺寸；只改内部 CSS 而不更新实际计算的做法不能通过验收。
- R6.AC4: 当第三方内容无法完整接入时，应明确列出具体消费者、范围与影响；范围内自有适配缺口保持待完成状态，不能通过静默豁免宣布全局完成。

### R7: 键盘、触屏与遥控器交互

**用户故事：**作为使用不同输入设备的用户，我希望放大后的界面既看得清，也能顺利操作。

**验收标准：**
- R7.AC1: 当使用键盘或遥控器时，当前焦点应清楚可见，聚焦项进入可视区域，逻辑焦点组之间的移动与返回可预测，关键操作不依赖鼠标 hover。
- R7.AC2: 当使用能向目标浏览器提供方向、确定和返回事件的遥控器时，表单、菜单、弹框及列表应遵循明确导航契约；字段输入使用目标环境输入法、系统软键盘或外接键盘，不自建电视输入法。方向导航不能劫持输入框光标或 Select 等控件自身按键语义。
- R7.AC3: 当弹框打开、关闭或操作移入更多菜单时，应正确接管和恢复焦点；切档与场景切换不得使焦点落入不可见或已移除元素。
- R7.AC4: 当鼠标与触屏并存时，交互目标应满足当前支持方式的约束；检测到某种输入设备不得悄悄修改显示比例，触屏关键任务不能依赖 hover 提示。

### R8: 状态连续性与偏好保存

**用户故事：**作为正在处理业务的用户，我希望调整显示不会丢失工作，并能记住适合当前设备的选择。

**验收标准：**
- R8.AC1: 当切换显示大小或使用场景时，系统应保留路由、未提交值、校验结果、筛选、选择和必要阅读位置；页面组合变化也不能通过重新挂载丢失编辑状态。
- R8.AC2: 当同一账号在当前浏览器再次进入某个场景时，应恢复该场景保存的选择；不同账号和匿名页面的个人偏好应隔离。
- R8.AC3: 当一个窗口修改显示设置时，另一个正在工作的窗口应保留当前有效选择；当前场景属于窗口状态，刷新恢复，新窗口按明确部署/入口的场景默认读取对应账号档位，不继承其他窗口的当前场景，不承诺自动识别物理显示器身份。
- R8.AC4: 当存储不可用、偏好损坏或值超出合法范围时，系统应安全回退到可用默认值，不阻断业务；持久化失败不撤销当前有效选择。
- R8.AC5: 当账号身份尚未确认时，系统应使用匿名或中性加载界面，不以最近账号推断当前用户；身份与有效尺寸就绪后再呈现首个可交互业务页面，退出立即切匿名状态。恢复默认只重置当前场景的显示偏好。

### R9: 主题方案保持统一

**用户故事：**作为使用不同 ZXUI 主题的用户，我希望显示大小功能与主题体验一致。

**验收标准：**
- R9.AC1: 当切换已登记主题或明暗模式时，Header、Sidebar、内容表面与控件应继续消费 ZXUI 主题，显示大小和场景选择保持不变。
- R9.AC2: 当发现业务硬编码或旧主题样式阻断效果时，应先确定实际生效路径与根因；业务布局/消费问题在业务修复，通用主题或组件问题在 ZXUI 修复。
- R9.AC3: 当修复范围内主题旁路时，业务不得新增竞争性的核心 `--el-*`/`--zx-*` 值或第二份主题映射；领域语义色、媒体内容和用户正文按其原有边界处理。

### R10: 公开能力可供其他业务复用

**用户故事：**作为接入 ZXUI 的其他业务开发者，我希望通过公开能力获得一致效果。

**验收标准：**
- R10.AC1: 当新业务通过 ZXUI 公开入口接入显示大小时，核心控件、尺寸继承和浮层行为应成立，不依赖 RuoYi 私有 CSS、主题路径解析或本地补写库类型。
- R10.AC2: 当业务提供表单列数、主要操作、表格列优先级及内容用途时，共享组件/布局应完成重复适配；业务不为四个档位逐页编写样式分支。
- R10.AC3: 当普通 DOM 与 JS 消费者读取尺寸时，应有公开且一致的有效尺寸与更新契约；作用域更新后不能分别读取到旧基准和新视觉尺寸。
- R10.AC4: 当新增页面、生成器模板或库示例时，应沿用文字/空间角色和共享布局约定；复用现有规范检查，仅增加能直接防止本次已确认回归的窄规则。

### R11: 旧设置与显式尺寸兼容

**用户故事：**作为现有产品用户和组件消费者，我希望升级后尺寸行为可解释、可迁移。

**验收标准：**
- R11.AC1: 当首次迁移旧 size 时，应一次性保留合法值作为原有 EP 消费链的兼容基础尺寸，初始显示档位为 100%，新安装使用 default；不将旧值扩散到原本固定 default 的 ZXUI 消费者，不将 small/large 换算成比例，并撤下旧选择器及其刷新行为。
- R11.AC2: 当组件有显式数值或 CSS 长度时，应遵守公开声明的原语义；可缩放默认值和命名预设与原始长度逃生口分别说明，不静默给全部显式数值乘倍率。
- R11.AC3: 当现有消费者升级且未设置新能力时，办公 100% 的默认与既有有效 size/density 解析保持兼容；迁移文档应公开兼容基础尺寸的来源和适用链，后续退出须明确迁移，不能暗中归一化。若必须破坏公开语义，应明确版本边界，不作为兼容补丁暗改。
- R11.AC4: 当修改主题或结构样式时，应修改其拥有者源文件并通过既有生成链更新产物；源代码直连与公开包消费使用同一契约。

### R12: 领域内容与覆盖边界

**用户故事：**作为使用图表、编辑器和专业工具的用户，我希望调整界面时业务含义保持不变。

**验收标准：**
- R12.AC1: 当调整显示大小时，图表/画布的工具栏、图例与 UI 标签应按已纳入的消费者契约适配，业务数据、拓扑坐标、仿真世界尺寸和文档内容不得被修改或写回。
- R12.AC2: 当保存、打印或导出业务内容时，结果不得因个人 UI 偏好改变领域尺寸和排版语义；应用界面截图不属于此项导出承诺。
- R12.AC3: 当嵌入独立文档或第三方 iframe 时，应明确宿主页与内部内容的作用域边界；自有可控内容通过明确契约接入，不能假设外层 CSS 自动穿透。
- R12.AC4: 当维护迁移清单和完成说明时，应分别列出已验证范围、待完成消费者、仿真专用后续范围与不可控制的外部内容；禁止把排除项、历史证据或仅源码扫描结果记为通过。

### R13: 浏览器与可访问性兼容

**用户故事：**作为依赖浏览器放大或辅助操作的用户，我希望产品显示设置与这些能力兼容。

**验收标准：**
- R13.AC1: 当使用浏览器原生缩放或系统显示缩放时，应用应保持其正常作用，不禁用缩放、不额外按设备像素比例重复放大 UI；命中区域与可见控件一致。
- R13.AC2: 当执行文本放大至 200%、窄至 320 CSS px 的重排检查及规定文字间距覆盖时，范围内关键任务应无内容或功能丢失；确需二维布局的表格/图形按适用例外单列并保持可访问。
- R13.AC3: 当验收交互目标时，应记录目标大小及适用间距/例外；不能把单一最小字号、125% 档位或通过若干截图当作无障碍合规证明。

### R14: 真实业务、跨仓库与多终端交付证据

**用户故事：**作为产品维护者，我希望完成声明建立在真实页面与可复用组件能力上。

**验收标准：**
- R14.AC1: 当定位和修复问题时，应先核对业务与库源码及实际消费者，再在所属层修改；开发验证优先使用 `VITE_ZXUI_LOCAL=true` 与 `VITE_ZXIO_REPO_ROOT=/Users/hqz/Downloads/element-plus`，无需先发布 npm。
- R14.AC2: 当验证首条业务链时，应覆盖外壳、筛选、表格/分页、多列表单、浮层、长内容、错误状态和切档保留输入；库 docs 与业务同契约验证，演示页或单测不能替代真实业务。
- R14.AC3: 当执行主题与尺寸验收时，应对登记的九个主题、明暗和四档做关键契约覆盖，再选择代表组合验证复杂交互；不要求每页执行全部笛卡尔积，但所有声明支持的组件类别均须有证据。
- R14.AC4: 当开始实施时，应登记目标浏览器/系统、设备及按键映射；交付时须有至少一组低高度笔记本、一组桌面、一组远距离电视/大屏，以及承诺支持的标准触屏与遥控器环境证据，记录可用视口、观看距离和文字输入方式。缺硬件时设备验收保持未完成，不能关闭多终端交付；模拟视口不能替代真机操作。
- R14.AC5: 当准备跨业务交付时，应通过一次公开包的本地安装消费验证，核对类型、样式资产与代表交互；不依赖源码别名兜底，不以正式 npm 发布为验收前置。
- R14.AC6: 当增补验证时，应优先复用现有检查和真实页面，只为尺寸组合、作用域/浮层、JS 同步或已复现缺陷增加必要回归测试；不为每页每档复制测试，不因未获得硬件或浏览器操作授权而伪造通过。
