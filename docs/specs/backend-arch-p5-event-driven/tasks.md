# 事件驱动架构实现任务

> 说明：本阶段验收范围不包含 `simulation/protocol/device` 相关模块，相关功能在后续阶段补齐。

- [x] 1. 建立领域事件模型与总线抽象
  - 定义统一 Domain Event 不可变模型与版本字段。
  - 实现 `IEventBus` 抽象与进程内总线实现。
  - 建立 handler 注册与装配机制。
  _需求追溯: R1.AC1, R1.AC2, R1.AC4, R2.AC1, R2.AC2_

- [x] 2. 在写路径接入领域事件产出
  - 在关键 CommandHandler 中产出标准事件。
  - 规范事件命名、聚合标识与元数据。
  - 确保事件进入统一发布流程。
  _需求追溯: R1.AC3, R1.AC4, R3.AC1_

- [x] 3. 落地 Transactional Outbox
  - 新增 Outbox 表与仓储。
  - 保证业务提交与 outbox 写入同事务原子性。
  - 实现状态字段与重试字段管理。
  _需求追溯: R3.AC1, R3.AC3, R3.AC4_

- [x] 4. 实现 Dispatcher 发布与失败重试
  - 开发后台轮询发布器。
  - 发布成功更新状态，失败执行指数退避。
  - 输出结构化日志和失败指标。
  _需求追溯: R2.AC3, R2.AC4, R3.AC2, R3.AC4, R6.AC1_

- [x] 5. 建立 Event History 与回放能力
  - 新增事件历史存储与查询 API。
  - 支持按聚合/类型/时间过滤。
  - 实现受控回放与审计日志。
  _需求追溯: R4.AC1, R4.AC2, R4.AC3, R4.AC4, R6.AC3_

- [x] 6. 实现幂等消费与跨模块编排
  - 建立 `event_id + handler` 去重机制。
  - 通过新增处理器实现跨模块副作用编排。
  - 处理器跨模块数据访问统一走 ports 接口。
  _需求追溯: R5.AC1, R5.AC2, R5.AC3, R5.AC4, R2.AC2_

- [x] 7. 建立观测与运维治理并验收
  - 接入 backlog、成功率、失败率、重试次数指标。
  - 增加积压告警与 trace/event 关联日志。
  - 执行事务闭环、重试、回放与故障注入回归测试。
  _需求追溯: R6.AC1, R6.AC2, R6.AC3, R6.AC4, R2.AC4_
