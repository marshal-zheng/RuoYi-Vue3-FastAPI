# 通用备注富文本与 JSON 存储需求规格

## 简介

将平台通用管理功能中的可编辑备注统一接入 `@zxio/text-editor`，采用用户已确认的 A 功能范围，以 ZXUI Document v2 JSON 作为唯一权威内容。统一覆盖编辑、保存、回显、只读展示、导入导出、生成器、初始化数据和历史数据迁移，避免只替换输入控件后留下字符串契约或不可升级的数据。

本文件创建于 2026-10-22。用户已确认 A 功能范围、JSON 存储方向及完整需求；需求确认原文为“需求没问题，继续生成 design.md，把 ZXUI 接入、前后端契约和历史数据迁移的具体方案设计清楚。”随后用户确认设计并授权 SSD auto 生成任务。本轮保持已确认的 59 条验收正文与编号不变，补充生成器模板边界的自动采用决定及审核状态。规格阶段不修改业务代码、不执行数据迁移、不发布包。

## 已确认决策与目标

- 产品范围：先解决通用管理备注；工程、版本、协议、端口等领域描述与备注暂不纳入。
- A 功能：段落、换行、加粗、斜体、有序列表、无序列表、链接、撤销与重做；2026-10-22 追加命名文字颜色（红、橙、绿、蓝、紫、灰，按名称存储，随明暗主题取色）。不增加图片、附件、表格、代码块、提及或协作。
- 交互形态（2026-10-23 用户确认，取代前一日决定）：AI 帮写和修改备注是首要入口，常驻紧凑格式栏提供加粗、命名文字颜色、列表和链接，更多菜单收纳斜体与清除格式。AI 支持整文/选区、流式候选、继续调整、明确采用及一次撤销；不使用逐段 diff 审阅，不自动保存业务记录。业务链路与交付范围见 [AI-first 落地计划](../../plans/2026-10-23-ai-first-remarks.md)。
- 存储方向：完整 ZXUI Document v2 文档作为唯一权威内容，使用数据库原生 JSON 列；HTML、纯文本和摘要均为派生输出。
- 架构方向：复用 ZXUI 文档、编辑与渲染能力，Python 后端使用一个共享的 A 子集契约完成边界校验、纯文本转换和导入适配；本轮不引入常驻 Node 服务。
- 演进方向：范围内前后端和数据一次收敛，不保留可同时写入字符串、HTML 和 JSON 的长期兼容接口。历史数据及明确的纯文本导入属于转换边界。
- 业务归属：权限、记录身份、表单会话与提交仍由现有业务承担；通用编辑器缺口在 ZXUI 修复；本轮不重写表单引擎或数据库交付体系。

## 需求列表

### R1: 范围明确且迁移完整

**用户故事:** 作为平台维护者，我希望本轮所有已确认的通用备注入口共同升级，以便统一使用体验且不误改领域内容。

**验收标准 (EARS):**

- R1.AC1: WHEN 实施本功能时，THEN 必须覆盖迁移范围表中的七个字段及其真实读写消费者，逐项记录编辑入口、读写类型、展示、导入导出、脚本和数据库的处置结果。
- R1.AC2: WHEN 发现同名备注、描述或 JSON 字段时，THEN 必须按业务用途和真实调用判断范围，不得依据字段名、长度或数据库类型批量迁移。
- R1.AC3: WHEN 完成本轮改造时，THEN 范围内运行时写接口只能接收统一文档或空值，相关旧字符串编辑路径必须移除；明确的纯文本导入及历史迁移入口按各自契约转换。
- R1.AC4: WHEN 共享组件、公共类型或模板发生变化时，THEN 必须检查范围外消费者，不得破坏其既有正文编辑或字符串备注行为，也不得把范围外未验收项计入本轮完成结果。

### R2: A 范围的基础富文本编辑

**用户故事:** 作为管理人员，我希望备注支持必要的排版，以便清楚表达说明、步骤和关联链接。

**验收标准 (EARS):**

- R2.AC1: WHEN 编辑非空备注时，THEN 编辑器必须支持段落、软换行、加粗、斜体、命名文字颜色、有序列表、无序列表、链接以及当前会话的撤销重做，并在保存与重新打开后保持内容及支持的格式。
- R2.AC2: WHEN 输入中文、组合字符、表情或使用输入法组合输入时，THEN 不得重复插入、丢失字符或在组合输入未结束时误提交表单；键盘焦点、选择和基础快捷键应可正常使用。
- R2.AC3: WHEN 粘贴外部富文本时，THEN 必须仅接纳 A 支持的格式；标题等可表达为正文的内容保留文字，表格或代码等不支持结构降为可读文字，图片与附件不得触发上传或保留隐藏资源，不能表示的非文本内容须给出提示。
- R2.AC4: WHEN 用户通过工具栏、快捷键、粘贴或其他编辑器入口操作时，THEN A 以外的节点与能力必须受到一致约束，不能只隐藏按钮而允许保存不支持内容。
- R2.AC5: WHEN 编辑器清空、撤销清空或在只读与禁用状态间切换时，THEN 值变化、空值归一化和交互状态必须一致；只读、禁用状态不得修改内容或意外提交。
- R2.AC6: WHEN 展示编辑限制时，THEN 必须区分正文字符限制与序列化文档资源限制，超限时提供可理解的错误并保留当前输入，不得静默截断。具体字符数、字节数、节点数和嵌套上限由技术设计统一确定并供前后端与边界测试使用。

### R3: 通过 ZXUI 公开能力完成接入

**用户故事:** 作为前端维护者，我希望复用 ZXUI 的成熟能力，以便所有备注共享一致的编辑、渲染和主题行为。

**验收标准 (EARS):**

- R3.AC1: WHEN 接入编辑器时，THEN 必须声明 `@zxio/text-editor` 依赖，使用公开类型、文档值绑定、渲染入口和样式出口；不得复制编辑器内核、访问包内私有路径或自行补写库公开类型。
- R3.AC2: WHEN 使用 `VITE_ZXUI_LOCAL=true` 与指定 ZXUI 工作区时，THEN text-editor 必须通过现有源码集成机制与主题体系生效；关闭源码模式后，实际候选包必须能通过公开导入完成类型检查与生产构建。
- R3.AC3: WHEN A 范围限制、Schema 表单适配、只读渲染或公开出口存在通用能力缺口时，THEN 必须先核对现有能力并在所属 ZXUI 包修复，业务仅保留备注策略、布局及业务流程，不得使用逐页补丁掩盖缺口。
- R3.AC4: WHEN 页面处于明暗主题、不同密度或弹框中的链接浮层场景时，THEN 编辑区、工具栏、焦点和错误状态必须遵循现有主题与浮层归属，不新增业务侧核心主题变量覆盖。
- R3.AC5: WHEN 展示备注列表或只读内容时，THEN 必须使用轻量摘要或公开只读渲染能力，不得为每个列表单元格创建可编辑实例，也不得因本轮 A 功能启用上传、协作或二进制导出服务。

### R4: 表单生命周期与值所有权一致

**用户故事:** 作为管理人员，我希望编辑备注时现有加载、保存、取消和权限行为保持可靠，以便不会误覆盖其他记录。

**验收标准 (EARS):**

- R4.AC1: WHEN 原生表单使用备注编辑器时，THEN 必须接入现有 FormDialog/FormGrid、校验与字段错误机制；备注按整行字段布局，不重复声明列数、标签宽度或间距策略。
- R4.AC2: WHEN 岗位等 Schema 表单使用备注时，THEN SchemaForm 必须是编辑值与验证的唯一所有者，组件注册、对象或空值模型、初值和 DTO 提取必须共同迁移，不得在业务壳另建一份可写文档。
- R4.AC3: WHEN 加载详情、快速切换记录、关闭重开或读取失败时，THEN 既有记录身份与读取会话保护必须继续生效，不得显示上一条备注、以默认空值覆盖未加载内容或携带上一条的撤销历史。
- R4.AC4: WHEN 内容回填或编辑器规范化文档时，THEN 未发生用户编辑的表单不得被误判为已修改；用户改变格式或正文则必须按既有规则触发未保存修改保护。
- R4.AC5: WHEN 保存失败、提交结果未知或校验被拒绝时，THEN 必须沿用既有错误反馈和结果核对机制，保留编辑值；保存成功后以服务端返回或重新读取的权威文档更新状态。

### R5: 单一 JSON 文档与 API 契约

**用户故事:** 作为接口维护者，我希望存储和传输使用明确的文档契约，以便前后端不再猜测字符串代表纯文本还是 HTML。

**验收标准 (EARS):**

- R5.AC1: WHEN 持久化范围内备注时，THEN 既有 `remark` 字段必须保存完整 Document v2 对象或数据库空值，正文为 `body.format='json'`；不得保存二次 JSON 编码的字符串、HTML 主内容或裸正文树替代完整文档。
- R5.AC2: WHEN A 备注文档被接受时，THEN 必须包含受支持的版本、元数据和合法且文档内唯一的块 ID；`assets`、`annotations` 为空集合，元数据只允许备注需要的受限内容，不引入页面、打印或批注契约。
- R5.AC3: WHEN 创建时未提供备注或用户明确清空备注时，THEN 必须统一保存为 SQL NULL；更新时字段未提供表示不修改，明确传 `null` 表示清空。空文档如何判定须在技术设计中固定，并不得以不加区分的 trim 丢失历史空白文本。
- R5.AC4: WHEN 接收不支持的文档版本、未知节点或属性、不合法块身份时，THEN 必须返回现有错误协议下可定位到备注的校验失败，不得静默降级为纯文本、吞掉格式或按旧字符串模式保存。
- R5.AC5: WHEN 更新备注时，THEN 服务端必须按整份文档替换持久化，并确保写入可被 ORM 正确跟踪；只更新其他字段的接口不得顺带重写或清空备注。
- R5.AC6: WHEN 发布接口改造时，THEN 写入 DTO、详情和嵌套响应、OpenAPI 产物、生成客户端、手写业务类型、模拟接口和数据必须同步；派生字段如 `remarkText` 只读且由服务端计算，不接受客户端作为权威内容写入。

### R6: 后端受限校验与安全边界

**用户故事:** 作为平台维护者，我希望接口直接调用与编辑器提交受到相同约束，以便非法内容不会绕过界面进入数据库。

**验收标准 (EARS):**

- R6.AC1: WHEN 任何范围内业务写入备注时，THEN 必须复用一个共享的 Python A 文档契约，校验节点类型、父子关系、标记、精确属性、版本、块 ID、资源集合和元数据；不能仅以 `dict` 或 JSON 可序列化作为通过条件。
- R6.AC2: WHEN 备注包含链接时，THEN 必须仅允许设计中固定的安全协议与明确的相对链接策略，并拒绝混淆或危险协议；浏览器只读输出仍需使用 ZXUI 的安全渲染策略，不得直接插入用户提交的 HTML。
- R6.AC3: WHEN 输入超过已定义的正文、字节、节点或深度预算时，THEN 必须在持久化前拒绝并定位原因；前端可提示但不能替代服务端限制，异常深层输入不得导致未处理的递归错误或部分保存。
- R6.AC4: WHEN 实现 Python 校验与纯文本转换时，THEN 只实现 A 所需边界并通过共享样例与 ZXUI 公开校验器核对，不引入整套 ProseMirror 内核复刻或常驻 Node 服务。
- R6.AC5: WHEN 校验失败或无权编辑所属记录时，THEN 现有鉴权、字段写入白名单及事务边界必须生效，业务记录不得部分更新，错误记录不得无必要地包含完整备注正文。
- R6.AC6: WHEN 升级 ZXUI 包或文档契约时，THEN 必须执行相同文档样例的接纳、保存、再次编辑和派生输出检查；无法无损接纳的版本变化须提供显式转换，不得靠永久多版本写入维持兼容。

### R7: 展示、导出与纯文本导入

**用户故事:** 作为管理人员，我希望备注在列表、详情和 Excel 中保持可读，以便富文本升级不影响日常查询与数据交换。

**验收标准 (EARS):**

- R7.AC1: WHEN 列表、提示或选择器需要展示备注时，THEN 必须展示由文档派生的可读文字或摘要，不显示 JSON、HTML 标签或对象字符串；摘要截断不得损坏 Unicode 字符。
- R7.AC2: WHEN 查看完整备注时，THEN 必须通过 ZXUI 公开只读能力保留 A 格式和安全链接，并明确区分无备注与读取失败。
- R7.AC3: WHEN 服务端导出 Excel 时，THEN 必须从已校验的权威文档派生纯文本，保留段落、换行及列表顺序，不依赖浏览器传来的摘要，不把 HTML 或 JSON 放入单元格；同时核对并保留既有单元格文字安全处理。
- R7.AC4: WHEN 既有导入入口支持备注列时，THEN 必须将该列按纯文本显式构造成合规文档，字面量 HTML、JSON 文本及公式样式文字不得被自动执行或猜测为其他内容格式；不存在备注导入能力的模块无需为本轮新增导入功能。
- R7.AC5: WHEN Excel 导出后重新导入时，THEN 文档必须说明该通道保留文本而不承诺富文本格式无损往返；已有完整数据备份或序列化流程若包含范围内字段，必须保留完整 JSON。
- R7.AC6: WHEN 缓存或关联接口消费范围内记录时，THEN 必须明确文档和纯文本的使用位置并处理既有缓存失效，避免返回旧字符串或把 JSON 误当字典标签、配置值等业务字段；本轮不新增无实际检索需求支持的持久化摘要列或索引。

### R8: 生成器、初始化与受管数据共同收敛

**用户故事:** 作为开发者，我希望系统生成和初始化的数据也遵循新契约，以便新页面、新库和重复同步不会重新引入字符串备注。

**验收标准 (EARS):**

- R8.AC1: WHEN 生成器表配置编辑备注时，THEN 必须与系统管理使用同一文档值和校验契约，详情、保存及 `gen_table` 数据库变更不得遗漏。
- R8.AC2: WHEN 为显式采用通用备注契约的字段生成代码时，THEN 普通与树形等受影响模板必须共同输出正确的编辑组件、初值、读写类型、列表展示和后端映射；预览与导出生成结果一致，不得因任意字段名或所有 JSON 类型触发富文本化。
- R8.AC3: WHEN bootstrap、种子数据、受管字典与配置声明写入范围内备注时，THEN 必须在明确的编译或导入边界转成合规文档，数据库和发布目标态不得继续存放旧字符串；声明仍可用纯文本编写，但不能变成业务 API 的字符串兼容模式。
- R8.AC4: WHEN 同一声明重复编译、同步、验证或部署时，THEN 输出文档、块 ID 和参与比较的内容必须稳定，不得因随机 ID、当前时间或 JSON 属性顺序制造持续差异；格式迁移本身不得重置既有受管数据所有权或覆盖非受管备注。
- R8.AC5: WHEN 完成生成器和数据源改造时，THEN 必须更新受影响的模拟数据、测试夹具和公开接入示例，并清理范围内失效的旧备注模板与处理分支；仍被范围外正文使用的编辑器模板应保留其明确职责。

### R9: 历史数据无损转换与可恢复切换

**用户故事:** 作为数据库维护者，我希望已有备注能可靠迁移，以便升级不会丢字、误解释内容或留下无法恢复的中间状态。

**验收标准 (EARS):**

- R9.AC1: WHEN 准备迁移目标环境时，THEN 必须先核对七个字段的真实结构、行数、空值、长度和异常值，输出只读预检报告及备份恢复条件；不得把本地样本当作其他环境已通过预检。
- R9.AC2: WHEN 转换旧纯文本时，THEN 必须按字面文本构造文档，保留中文、表情、特殊字符、前后空格、连续空行和行序；仅允许明确记录的换行编码归一化，`<p>`、JSON 外观文本不得被推断解析为富文本或文档。
- R9.AC3: WHEN 迁移 NULL 和空字符串时，THEN 必须按已定义规则转换为空备注；其他非空历史文本须通过正文等价验证，不得用空值兜底、静默截断或仅比较总行数证明无损。
- R9.AC4: WHEN 迁移数据超出新限制或出现转换失败时，THEN 必须在删除旧值前停止并提供表、主键、阶段及可执行的处理指引，不能为通过迁移而丢弃记录或放宽运行时契约。
- R9.AC5: WHEN 执行改列与回填时，THEN 必须使用能保存原值直至核对完成的有序过程，兼顾 MySQL DDL 非整体事务的实际行为；迁移需识别未开始、已完成和中断状态，重复执行不得重复包装文档或覆盖已验证内容。
- R9.AC6: WHEN 切换新代码与新列时，THEN 必须明确暂停相关写入、备份、转换、逐行核对、启用新版本与最终验证的顺序；中途失败能按记录的阶段恢复，成功后不保留永久双写列，恢复方案不得将新富文本无提示地降回旧 `VARCHAR(500)`。
