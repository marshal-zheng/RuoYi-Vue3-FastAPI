# 项目导入示例文件

本目录包含用于验证系统功能的项目导入示例文件。

## 文件说明

### collision-congestion-test.json

**用途**: 验证运行期冲突、丢包、拥塞检测与告警展示功能

**包含场景**:

1. **CAN总线仲裁冲突**
   - 3个设备（主控器 + 2个从机）连接到同一CAN总线
   - 所有设备使用相同的CAN ID (0x120 = 288)
   - 频率：50ms，会产生ID冲突需要仲裁
   - **预期告警**: CAN仲裁冲突、多设备竞争总线

2. **RS485半双工冲突**
   - RS485主机和从机以相同频率(80ms)发送数据
   - 半双工总线同时发送会产生冲突
   - **预期告警**: RS485总线冲突、退避重传

3. **LAN网络拥塞**
   - 服务器配置低可视化带宽(0.5Mbps)
   - 高频发送大帧(1024字节 @ 20ms = ~400Kbps)
   - 负载率会超过80%触发拥塞告警
   - **预期告警**: 带宽拥塞、负载率超限

## 导入步骤

### 方式1: 通过界面导入

1. 登录系统
2. 进入"工程管理"页面
3. 点击"导入工程"按钮
4. 选择 `collision-congestion-test.json` 文件
5. 确认导入

### 方式2: 通过API导入

```bash
curl -X POST http://localhost:8000/api/v1/project/import \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer YOUR_TOKEN" \
  -d @collision-congestion-test.json
```

## 验证步骤

### 1. 导入后检查

- 查看工程列表，应出现"冲突拥塞告警验证工程"
- 进入工程详情，检查版本"冲突拥塞测试版本"是否存在
- 检查设备库是否包含7个设备（CAN主控器、2个CAN从机、RS485主从机、LAN服务器/客户端）

### 2. 进入仿真

1. 打开工程，选择版本"v1.0"
2. 点击"进入仿真"
3. 拓扑画布应显示完整的设备连接关系

### 3. 启动前校验

- 点击"启动仿真"前，系统应弹出健康检查对话框
- 检查是否显示以下警告：
  - ⚠️ 多连接检测：CAN端口存在多连接（总线型多连接）
  - ⚠️ 协议不匹配：无（因为都正确匹配）

### 4. 运行仿真

启动仿真后，观察告警面板：

#### CAN冲突告警
- **告警类型**: collision（冲突）
- **严重程度**: error
- **消息**: 检测到报文冲突：设备同时竞争总线
- **验证方式**: 点击告警项，相关CAN设备节点应高亮标红并闪烁

#### RS485冲突告警
- **告警类型**: collision（冲突）
- **严重程度**: error  
- **消息**: 总线冲突，检测到退避重传
- **验证方式**: 点击告警项，RS485主从机节点应高亮标红

#### LAN拥塞告警
- **告警类型**: congestion（拥塞）或 bandwidth_exceed（超限）
- **严重程度**: warning/error
- **消息**: 负载率超过80%，存在拥塞风险
- **验证方式**: 
  - 查看带宽监控面板，负载率应显示>80%
  - 曲线颜色应变为黄色/红色
  - 点击告警项，LAN服务器节点应高亮

### 5. 带宽曲线验证

- 带宽监控面板应显示实时曲线
- 切换"汇总"/"按端口"视图，曲线应正确切换
- 鼠标悬停在曲线上，应显示tooltip浮层
- 观察10分钟（600秒），曲线应持续显示不丢失历史数据

### 6. 协议分析器验证

- 底部协议分析器应实时显示报文列表
- 报文应包含：CAN帧、RS485帧、LAN帧
- 字段应正确解析：
  - CAN: counter字段递增
  - RS485: cmd字段循环(1,2,3,4,5)
  - LAN: 随机数据
- 点击报文行，链路应播放流量动画

## 预期告警统计

运行5分钟后，告警统计卡片应显示：

- **严重**: 0-2条（取决于冲突频率）
- **错误**: 5-20条（CAN冲突、RS485冲突）
- **警告**: 10-50条（LAN拥塞、多连接警告）
- **总计**: 15-70条

## 故障排查

### 导入失败

1. 检查JSON格式是否正确（使用 jsonlint 验证）
2. 检查后端日志，查看具体错误信息
3. 确认数据库表已创建（device、project、project_version、project_topology）

### 仿真无告警

1. 检查后端日志，确认协议模型是否正确启动
2. 检查WebSocket连接是否正常（浏览器控制台Network标签）
3. 检查告警检测器是否正确配置

### 节点不高亮

1. 刷新页面重新进入仿真
2. 检查浏览器控制台是否有JavaScript错误
3. 确认X6图形库版本兼容性

## 技术说明

### CAN冲突仿真原理

- 使用 `simpy.PriorityResource` 实现总线仲裁
- 相同ID的多个设备同时申请总线时，SimPy会按优先级调度
- 冲突检测：监控总线资源的请求队列长度
- 仲裁结果：ID较小的优先获得总线

### RS485冲突仿真原理

- 使用 `simpy.Resource(capacity=1)` 模拟半双工总线
- 发送前检查 `bus.count > 0` 判断总线是否忙
- 检测到冲突后触发退避机制(BACKOFF_TIME=1ms)
- 冲突计数器累加，生成冲突告警

### LAN拥塞仿真原理

- 使用 `simpy.Store` 模拟交换机缓冲区
- 计算实时带宽：`(字节数 * 8) / (时间窗口 * 1000000)` Mbps
- 负载率计算：`(实时带宽 / 配置带宽) * 100%`
- 阈值告警：负载率>80%警告，>95%错误
