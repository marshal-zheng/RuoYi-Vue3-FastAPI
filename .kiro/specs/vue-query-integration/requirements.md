# Vue Query (TanStack Query) 集成需求文档

## 1. 项目背景

### 1.1 当前状态
- **前端框架**: Vue 3.4.15 + Composition API + TypeScript
- **状态管理**: Pinia 2.1.7
- **HTTP 客户端**: 
  - 底层: @zxio/http (基于 Axios 0.28.1)
  - 兼容层: src/utils/request.ts
- **数据获取模式**: 
  - 手动管理 loading 状态
  - 组件内直接调用 API
  - 缺乏统一的缓存策略
  - 重复的错误处理逻辑

### 1.2 痛点分析
1. **重复的样板代码**: 每个组件都需要手动管理 loading、error、data 状态
2. **缺乏缓存机制**: 相同数据的重复请求，浪费带宽和服务器资源
3. **状态同步困难**: 多个组件使用相同数据时，状态不一致
4. **乐观更新复杂**: 实现乐观更新需要大量手动代码
5. **后台刷新缺失**: 无法自动在后台更新过期数据
6. **分页/无限滚动**: 需要手动实现复杂的分页逻辑

### 1.3 目标
集成 TanStack Query v5，实现：
- **零配置缓存**: 自动缓存和重用数据
- **后台同步**: 自动在后台刷新过期数据
- **乐观更新**: 简化 UI 更新逻辑
- **请求去重**: 自动合并重复请求
- **向后兼容**: 不破坏现有代码，渐进式迁移
- **世界级实践**: 对齐顶级项目的架构模式

## 2. 用户故事

### 2.1 开发者体验优化

**US-2.1.1: 作为前端开发者，我希望使用声明式 API 获取数据**
- 使用 `useQuery` 替代手动管理 loading/error/data
- 自动处理请求状态和错误
- 验收标准:
  - 组件代码减少 30% 以上
  - 无需手动管理 loading 状态
  - 错误处理自动化

**US-2.1.2: 作为前端开发者，我希望数据自动缓存和重用**
- 相同查询自动返回缓存数据
- 后台自动刷新过期数据
- 验收标准:
  - 重复请求减少 70% 以上
  - 页面切换时立即显示缓存数据
  - 数据在后台自动更新

**US-2.1.3: 作为前端开发者，我希望轻松实现乐观更新**
- 使用 `useMutation` 简化更新逻辑
- 自动回滚失败的更新
- 验收标准:
  - UI 立即响应用户操作
  - 失败时自动回滚
  - 成功后自动刷新相关查询

### 2.2 架构优化

**US-2.2.1: 作为架构师，我希望采用分层架构**
- API 层: 纯函数，返回 Promise
- Query 层: 封装 useQuery/useMutation
- View 层: 只关注 UI 逻辑
- 验收标准:
  - 清晰的职责分离
  - 易于测试和维护
  - 代码复用性高

**US-2.2.2: 作为架构师，我希望保持向后兼容**
- 现有 API 调用继续工作
- 渐进式迁移，不需要一次性重写
- 验收标准:
  - 现有代码无需修改
  - 新旧代码可以共存
  - 提供迁移指南

### 2.3 性能优化

**US-2.3.1: 作为用户，我希望页面加载更快**
- 利用缓存减少网络请求
- 预取关键数据
- 验收标准:
  - 首次加载时间不变
  - 二次加载时间减少 50%
  - 网络请求减少 60%

**US-2.3.2: 作为用户，我希望 UI 响应更流畅**
- 乐观更新提供即时反馈
- 后台刷新不阻塞 UI
- 验收标准:
  - 操作响应时间 < 100ms
  - 无明显的加载闪烁
  - 数据更新平滑过渡

## 3. 功能需求

### 3.1 核心功能

#### 3.1.1 Query 管理
- **FR-3.1.1.1**: 支持 useQuery 进行数据查询
  - 自动管理 loading/error/data 状态
  - 支持查询键（Query Key）管理
  - 支持查询选项配置（staleTime, cacheTime, refetchOnWindowFocus 等）
  
- **FR-3.1.1.2**: 支持 useMutation 进行数据变更
  - 支持乐观更新
  - 自动失败回滚
  - 成功后自动刷新相关查询

- **FR-3.1.1.3**: 支持查询失效和重新获取
  - 手动失效查询
  - 自动后台刷新
  - 条件性重新获取

#### 3.1.2 缓存策略
- **FR-3.1.2.1**: 智能缓存管理
  - 基于查询键的缓存
  - 可配置的缓存时间
  - 自动垃圾回收

- **FR-3.1.2.2**: 缓存更新策略
  - 后台自动更新
  - 窗口聚焦时刷新
  - 网络重连时刷新

#### 3.1.3 分页和无限滚动
- **FR-3.1.3.1**: 支持分页查询
  - useQuery 配合分页参数
  - 自动缓存每一页
  - 页面切换无延迟

- **FR-3.1.3.2**: 支持无限滚动
  - useInfiniteQuery 实现
  - 自动加载下一页
  - 双向滚动支持

### 3.2 集成功能

#### 3.2.1 与现有架构集成
- **FR-3.2.1.1**: 兼容 @zxio/http
  - Query 层使用现有 HTTP 客户端
  - 保持统一的错误处理
  - 保持统一的认证机制

- **FR-3.2.1.2**: 兼容 Pinia
  - Query 管理服务器状态
  - Pinia 管理客户端状态
  - 清晰的职责划分

- **FR-3.2.1.3**: 兼容现有 API 层
  - 复用现有 API 函数
  - 无需重写 API 调用
  - 渐进式迁移

#### 3.2.2 开发工具
- **FR-3.2.2.1**: 集成 Vue Query DevTools
  - 可视化查询状态
  - 实时监控缓存
  - 手动触发操作

- **FR-3.2.2.2**: TypeScript 支持
  - 完整的类型推断
  - 类型安全的查询键
  - 类型安全的响应数据

### 3.3 高级功能

#### 3.3.1 预取和预加载
- **FR-3.3.1.1**: 支持数据预取
  - 路由切换前预取
  - 鼠标悬停时预取
  - 条件性预取

- **FR-3.3.1.2**: 支持初始数据
  - SSR 数据注入
  - 占位数据
  - 从缓存初始化

#### 3.3.2 依赖查询
- **FR-3.3.2.1**: 支持串行查询
  - 基于前一个查询结果
  - 自动管理依赖关系
  - 条件性启用

- **FR-3.3.2.2**: 支持并行查询
  - 同时发起多个查询
  - 统一管理状态
  - 批量错误处理

## 5. 技术约束

### 5.1 技术栈约束
- 必须使用 @tanstack/vue-query v5.x
- 必须兼容 Vue 3.4.15
- 必须兼容 @zxio/http
- 必须兼容 Pinia 2.1.7

### 5.2 架构约束
- 采用分层架构（API Layer → Query Layer → View Layer）
- Query 层集中管理所有查询
- 保持现有 API 层不变
- 不破坏现有 Pinia stores

### 5.3 迁移约束
- 支持渐进式迁移
- 新旧代码可以共存
- 不强制一次性重写
- 提供自动化迁移工具（可选）
