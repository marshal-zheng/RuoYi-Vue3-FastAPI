# 仿真页面权限降级处理

## 问题描述

**场景**：用户只给某个角色分配了工程权限（`project:project:*`）和仿真权限（`simulation:use`），但没有分配设备和协议模块的权限。

**现象**：进入仿真页面后，虽然拓扑图能正常渲染，但会弹出"当前操作没有权限"的错误提示，影响用户体验。

## 原因分析

仿真页面在加载时会调用多个 API：

| API | 权限要求 | 必需性 | 说明 |
|-----|---------|--------|------|
| `GET /project/{projectId}` | `project:project:query` | ✅ 必需 | 获取工程信息 |
| `GET /project/topology/{projectId}` | `project:project:query` | ✅ 必需 | 获取拓扑数据（画布渲染必需） |
| `GET /device/list` | `device:list:list` | ❌ 可选 | 获取设备库（用于拖拽添加新设备） |

**问题根源**：
- 设备列表 API 调用失败时，axios 响应拦截器会先于 try-catch 弹出错误通知
- 仿真页面主要功能是**运行已有拓扑**，设备库不是必需功能
- 应该支持**优雅降级**：无权限时静默处理，不影响主功能

## 解决方案

### 1. 前端请求拦截器支持静默错误模式

**文件**：`ruoyi-fastapi-frontend/src/utils/request.ts`

在响应拦截器中添加 `silentError` 配置支持：

```typescript
// 响应拦截器
service.interceptors.response.use(
  (res: AxiosResponse) => {
    const code = res.data.code || 200;
    const msg = errorCode[code] || res.data.msg || errorCode['default'];
    // 检查是否为静默模式（不弹出错误提示）
    const silentError = (res.config as any)?.silentError === true;
    
    // ... 其他逻辑
    
    } else if (code !== 200) {
      if (!silentError) {
        ElNotification.error({ title: msg });
      }
      return Promise.reject('error');
    }
    // ...
  },
  (error: any) => {
    const silentError = (error.config as any)?.silentError === true;
    // ...
    if (!silentError) {
      ElMessage({ message: message, type: 'error', duration: 5 * 1000 });
    }
    return Promise.reject(error);
  }
);
```

### 2. API 函数添加 options 参数

**文件**：`ruoyi-fastapi-frontend/src/api/device/device.js`

```javascript
// 查询设备列表
export function listDevice(query, options = {}) {
  return request({
    url: '/device/list',
    method: 'get',
    params: query,
    ...options,  // 支持传递 silentError 等配置
  });
}
```

**文件**：`ruoyi-fastapi-frontend/src/api/project/project.js`

```javascript
// 查询工程详细
export function getProject(projectId, options = {}) {
  return request({
    url: '/project/' + projectId,
    method: 'get',
    ...options,
  });
}
```

**文件**：`ruoyi-fastapi-frontend/src/api/project/topology.js`

```javascript
// 获取工程拓扑数据（可选按版本维度）
export function getProjectTopology(projectId, versionId, options = {}) {
  return request({
    url: '/project/topology/' + projectId,
    method: 'get',
    params: versionId ? { version_id: versionId } : undefined,
    ...options,
  });
}
```

### 3. 仿真页面使用静默模式

**文件**：`ruoyi-fastapi-frontend/src/views/project/simulation/index.vue`

```javascript
// 加载项目信息（无权限时静默降级）
async function loadProjectInfo() {
  try {
    const res = await getProject(projectId.value, { silentError: true });
    projectName.value = res.data?.projectName || "未命名工程";
  } catch (err) {
    console.warn("[仿真] 无法获取工程信息，可能缺少 project:project:query 权限");
    projectName.value = "未命名工程";
  }
}

// 加载设备列表（无权限时静默降级，不影响仿真主功能）
async function loadDeviceList() {
  loading.value = true;
  try {
    const response = await listDevice({}, { silentError: true });
    const devices = response?.rows || [];
    operators.value = devices.map((device) => ({
      // ... 映射逻辑
    }));
  } catch (err) {
    // 无设备列表权限时静默降级，仅在控制台记录
    console.warn("[仿真] 无法加载设备库，可能缺少 device:list:list 权限");
    operators.value = [];
  } finally {
    loading.value = false;
  }
}

// 从后端加载并回显已保存的拓扑数据
function restoreSavedTopology() {
  // ...
  getProjectTopology(projectId.value, versionId.value, { silentError: true })
    .then((res) => {
      // ... 正常处理
    })
    .catch((err) => {
      console.warn("[仿真] 无法加载拓扑数据，可能缺少 project:project:query 权限", err);
      ElMessage.warning("无法加载拓扑数据，请检查权限配置");
    });
}
```

## 效果对比

| 场景 | 修改前 | 修改后 |
|------|--------|--------|
| 无 `device:list:list` 权限 | ❌ 弹出"当前操作没有权限"错误提示 | ✅ 静默降级，设备库为空（不影响仿真运行） |
| 无 `project:project:query` 权限 | ❌ 弹出错误提示 | ✅ 静默降级 + 友好提示 |

## 权限配置建议

如果只想让某角色使用仿真功能，建议授予以下**最小权限集**：

| 权限 | 必需性 | 说明 |
|------|--------|------|
| `simulation:use` | ✅ 必需 | 仿真操作（启动/停止/控制等） |
| `project:project:query` | ✅ 必需 | 工程查询（获取拓扑数据必需） |
| `device:list:list` | ❌ 可选 | 设备库（用于拖拽添加新设备，仿真场景通常不需要） |

**注意**：如果用户不需要在仿真页面添加新设备，可以不授予 `device:list:list` 权限，前端会自动降级处理。

## 技术要点

1. **静默错误模式**：通过 `silentError: true` 配置，让某些"可选"的 API 调用失败时不弹出错误提示
2. **优雅降级**：前端在 try-catch 中处理权限错误，提供默认值或空数据，保证主功能可用
3. **通用性**：该方案是通用逻辑，可以应用到其他需要权限降级的场景
